## 1. 目标与范围

能力演进候选为：**稳定发布 → 数据可信 → 查谱体验 → 档案与寻根 → 按需规模化**；投资顺序改为**问题验证 → 交付验证 → 付费验证 → 复用验证 → 独立托管验证**。客户需要的成果决定本阶段选择哪些能力，不要求先完成整条功能路线才验证购买意愿。

近期计划拆分为 29 个开发工作包和 3 个前置决策工作包；长期另设 8 个产品工作包和 8 个商业工作包，共 48 个工作包。长期任务按需求和经营验证结果启动，不与近期任务一起默认承诺。

阅读顺序：第 3～8 章为近期任务；第 12 章为长期路线；第 13～16 章为变现方式、长期任务、商业任务和经营指标；第 17 章为首个 90 天安排。每个开发工作包可继续按“契约/后端、前端、回归”拆成提交，但必须按完整验收标准交付，不能以页面出现或接口返回成功代替功能完成。

| 领域 | 当前基线 | 后续应补齐的部分 |

| 事件与轨迹 | 事件维护、GPX 上传、多人有序关联、终点导航 | 内置地图、时间线、更多信息筛选 |

| 暂缓能力 | OCR 实验代码保留但未挂载；无离线编辑同步 | 不把历史文档中的“完成”当成当前可用 |

### 1.2 本轮不做的事

- 不把 SQLite 改为主存储，不启用静默 localStorage 兜底或自动上传历史数据。
- 不默认恢复 OCR，不做自动姓名改写、无证据的人物合并或亲属关系推断。
- 不立即重写 API、替换 ECharts、引入第二套 UI 框架或多租户架构。
- 不承诺匿名公开族谱、公开分享链接、复杂亲属称谓计算或自动离线合并。
- 不因本计划而部署、修改生产数据、创建 Issue、提交代码、推送或打 tag。

## 2. 排期与交付规则

### 2.1 里程碑

| 里程碑 | 优先级 | 建议范围 | 完成标志 |
| --- | --- | --- | --- |
| M0 稳定发布基线 | P0 | 6 个工作包，结合认证实施与运营基线估工 | 核心流程、真机和发布恢复路径有明确证据 |
| M1 数据维护可追溯 | P0 | 7 个工作包，优先核心核对与安全写入闭环 | 能人工核对、准确提交、追溯修改并处理冲突 |
| M2 查谱与导出体验 | P1 | 6 个工作包，按试点选择子集 | 普通用户查人查关系更直接；受控导出可用 |
| M3 档案与寻根增强 | P1/P2 | 5 个工作包，按需求独立排期 | 日期与地点信息可维护、可浏览；地图可用 |
| M4 规模化与协作 | P2/条件启动，备份基础为 P0 | 5 个工作包；基础恢复能力提前 | 性能有基线，必要优化和协作逐项交付 |
| G 前置决策 | G-01/G-02 基础部分在真实资料上线前 | 3 个工作包；决策后必须安排实施与复验 | 决策、适用范围、成本和负责人记录清楚 |

此前 M0～M3 的 8～12 周属于未校准的乐观估计，现撤回作为排期依据。项目企划对软件化最小运营场景初估 46～70 个有效工程人日，加约 25% 余量后约 58～88 人日；单工程主责兼顾日常工作时约 4～8 个月，仅为条件测算，不是当前应批准的投入。该区间未按 v0.1.7 的剩余工作重新校准，不能把已有认证与移动功能重复估为新开发，也不能直接按功能数量扣减人日。成果型服务采用受控人工流程时须重新估工，不自动删减安全控制或扣除工作包。前期先确认首发成果、安全范围和阶段上限，再校准。访谈、核对、采购和售后不视为免费并行产能。

### 2.2 状态与依赖

- 默认状态为“待排期”；遇到未决产品规则标记“待决策”，不能自行把建议实现为既定需求。
- 状态流转：待排期 → 待决策/开发中 → 待验收 → 已完成；受阻时记录原因和解除条件。
- 以下“依赖”是进入完整验收前必须满足的条件；无依赖的工作可以独立推进。
- 数据语义变化先完成契约设计，再做 API、界面和备份；角色规则必须同时落实到服务端。
- 每个任务记录负责人、实际起止日期、关联变更和验收证据，初始不虚构负责人或进度。

### 2.3 首期工作包选择与人工替代边界

以[企划书第 4 章](projectProposal.md#4-产品范围与取舍)的必做/受控人工/延期范围表选择任务。身份、权限、授权、客户边界、数据完整性和恢复要求不降级；报价、核对协调、影响清单复核与交接可评估人工流程，但先记录适用范围、版本、执行与复核人、失败处理和全部工时。

核对工作台、复杂审计查询 UI、订单自动化与其他便利性只有在成果需要或瓶颈被证明时建设。人工记录不能替代服务端权限、事务、修订控制或必需的审计证据；文件交付也需要访问保护、授权与恢复。此处不是批准某项功能删减，也不证明替代流程已安全可用。

每阶段现金、工时/工程人日上限与截止日尚待确认。没有批准不开展新增采购、招聘、收费或商业交付；先后顺序不能替代资源批准。48 个工作包的完成数量不是首阶段通过指标。

## 3. M0：稳定发布基线

- **目标与入口**：从 README 和文档索引能区分“当前可用”“待验收”“历史方案”“暂缓”。
- **拆分任务**：以 v0.1.7 对齐当前路由与页面；承接已完成的文档重组，核对旧 Stage2 路线中过期的存储、OCR 和角色描述；梳理开发、部署、发布入口；统一 README、产品说明与本计划的功能摘要。
- **边界**：保留历史记录，不把历史“已完成”百分比沿用为新进度；未经实际确认，不写“生产已验收”。
- **涉及位置**：`README.md`、`docs/README.md`、`docs/product/overview.md`、`docs/archive/stage2-plan.md`、`docs/implementation/stage3.md`、`docs/guides/deployment.md`。
- **验收**：新读者能定位真实 Worker 入口 `api/index.ts`、在线 D1 主存储、备份边界及暂缓功能；所有相对链接有效。
- **依赖**：无。本次新增计划和入口链接只完成其中一部分，不代表整个工作包完成。

### M0-02 建立核心浏览器回归与 CI 门禁

- **目标与入口**：覆盖登录到业务保存的完整用户操作，而非仅验证静态布局。
- **拆分任务**：复用现有 Playwright 配置及登录、独立密码、强制改密、移动布局和大字模式用例；补齐登录/退出、角色路由及成员、配偶、搜索分页、Markdown、备份、轨迹的完整业务闭环；将浏览器回归加入 CI。
- **异常场景**：登录失效、写入失败、连续点击保存、文件解析失败、空数据、长姓名、筛选后页码越界；失败时保留必要截图和 trace。
- **涉及位置**：`tests/browser/`、`playwright.config.ts`、`.github/workflows/ci.yml`；新增用例优先复用隔离模拟数据。
- **验收**：桌面与手机布局项目运行关键流程；失败会阻止发布；测试不访问生产 D1、不使用真实账号或族谱。模拟 API 用例不冒充真实 Worker 集成验证。
- **依赖**：无；后续功能按需扩展用例，不在第一轮穷举所有未来功能。

### M0-03 建立真实 Worker/D1 集成场景

- **目标**：确认浏览器以外的保存契约、事务和权限边界。
- **拆分任务**：梳理已有 API 测试与模拟覆盖；补独立本地测试库上的迁移、读取、保存、恢复、权限、CAS 冲突和事务回滚场景；为两客户端读取同一修订号再竞争保存提供用例。
- **数据边界**：初始化、清理仅作用于明确隔离的测试库；覆盖旧库迁移和已自动升级数据库，避免重复执行非幂等迁移。
- **涉及位置**：`api/index.ts`、`migrations/`、`tests/api/familyData.test.ts`、测试辅助代码。
- **验收**：普通用户写请求被拒绝；过期修订号不能覆盖新数据；失败不留下部分写入；空库不会自动 seed；业务备份不包含账号和会话。
- **依赖**：无。新增运行方式先在仓库中形成明确命令，再接入 CI，不在文档中宣称未实现的命令已可用。

### M0-04 移动真机验收与缺陷闭环

- **目标与入口**：iOS Safari、Android Chrome 上完成浏览和维护的关键操作。
- **拆分任务**：检查 320～430px 常见窄屏、横竖屏、长内容、软键盘遮挡、弹窗滚动、抽屉关闭、图谱手势、卡片追加和原生文件选择器；记录设备、系统、浏览器版本与结果。
- **重点场景**：GPX 从文件提供方选择；轨迹多人排序；连续展开树节点；搜索定位后查看档案；表单错误后继续编辑。
- **涉及位置**：`WorkspaceLayout.vue` 所在布局目录、`MemberCardList.vue`、`FamilyTreeChart.vue`、`ActivityManager.vue` 和相关样式。
- **验收**：页面根节点无横向溢出，图谱/表格仍可内部滚动；关键点击目标不小于 44px；输入不被遮挡；失败不丢表单。模拟器与真机证据分开记录。
- **依赖**：无；M0-02 提供自动回归支持，但不能替代本项真机验收。

### M0-05 发布、备份与回退清单

- **目标**：每次发布都能回答“发布了什么、能否恢复、如何确认正常”。
- **拆分任务**：发布前导出并验证业务备份；记录当前应用版本与数据库迁移状态；定义发布后只读冒烟检查；完成基础备份新鲜度告警、授权隔离恢复演练、责任人与替补配置；建立旧应用回退兼容性步骤。
- **边界**：代码回退不等于数据库回退；业务 JSON/SQLite 不能恢复账号和会话；生产演练或恢复必须另获授权。
- **涉及位置**：`docs/guides/deployment.md`、`changelog.md`、发布相关工作流；认证升级须同时遵守 `docs/guides/login.md`，不得常规回退至旧免密版本。
- **验收**：发布同步更新 `package.json`、`package-lock.json` 根包版本和对应 `v<版本号>` tag；记录每条验证命令及实际结果；明确哪些版本不能直接回退。真实资料上线前必须具有已验证的基础恢复路径，不能等待 M4 的规模化运营优化。
- **依赖**：M0-02、M0-03、M0-04。仅制定清单不触发提交、tag 或部署。

### M0-06 统一故障提示与诊断线索

- **目标与入口**：维护页和系统诊断能区分网络失败、未登录、无权限、校验失败、冲突和服务端故障。
- **拆分任务**：梳理 API 错误码到界面提示的映射；提供可理解的重试/重新登录/重新加载动作；为服务端日志和客户端错误提供关联标识；检查错误状态是否阻止误报成功；建立关键链路、错误率和备份新鲜度监控，验证主责与替补能收到告警。
- **隐私边界**：诊断默认只含版本、错误码、时间、请求标识和汇总计数，不记录 token、手机号、完整谱文、照片地址或坐标。
- **涉及位置**：`src/services/d1ApiService.ts`、`src/stores/familyStore.ts`、`src/pages/SystemPage.vue`、`api/index.ts`。
- **验收**：每类故障有明确提示和可执行下一步；重复请求不会产生成功假象；诊断内容可用于定位且不包含敏感正文；故障不仅能被用户看到，也能被指定人员发现并处理。
- **依赖**：无。

## 4. M1：数据维护可追溯

### M1-01 核对记录与数据演进契约

- **目标**：先定义人工核对和追溯的数据语义，避免在多个页面分别造状态。
- **拆分任务**：定义导入批次、源文件摘要、解析器版本、来源位置、候选项、人工决定及理由；区分解析出的 `matched/missing/ambiguous` 与人工“待核对/确认/驳回/保留疑点”状态。
- **关键规则**：确认关联不等于合并人物；驳回候选不等于删除原文；不把临时预览 ID 当作跨批次稳定 ID；生父与承继父继续独立。
- **数据变更**：先明确哪些证据随族谱业务备份保留、哪些操作人信息仅存服务端审计；若扩展持久化业务格式，显式升级 schema 并实现迁移，不静默丢弃新增字段。
- **验收**：有覆盖旧 schema、缺失字段、重复决定、失效候选、未知新版本的契约样例；JSON/SQLite 往返保存证据一致；旧备份导入能说明缺失的历史证据。
- **依赖**：M0-01；审计身份与保留期由 G-02 确认。

### M1-02 服务端操作审计与查询

- **目标与入口**：系统管理中查询谁在何时执行了哪类变更，发生在哪个修订号。
- **拆分任务**：记录新增/编辑/删除、Markdown 导入、备份恢复及人工确认；提供按操作类型、时间、操作者的分页查询；显示受影响对象数量和经授权的字段差异。
- **实现边界**：操作者来自服务端会话，不能信任客户端传入身份；业务写入与成功审计原子提交；失败尝试与成功事件区分；旧全量保存入口不能绕过审计。
- **数据变更**：新增服务端审计存储与查询接口；确定差异保存范围、保留期和访问权限；不把完整账号、会话或无限量业务快照塞进审计。
- **验收**：业务成功必有对应记录；业务失败不能出现成功记录；未授权访问被拒绝；分页稳定；账号删除后的展示规则明确。审计查询不等于自动撤销功能。
- **依赖**：M1-01、M0-03、G-02。

### M1-03 人工核对工作台

- **目标与入口**：维护页“资料与备份 → Markdown 预览 → 问题清单”可以真正处理问题，而不只是查看。
- **拆分任务**：按问题类型、世代、分支、核对状态筛选；并排展示原文行、解析结果、候选档案与关联依据；提供确认指定候选、驳回候选、保留疑点和撤销本次决定。
- **交互规则**：同名候选展示 ID、分支、父亲与代数；按条确认高风险关系；禁止“一键接受所有模糊匹配”；决定未提交前不修改正式族谱。
- **涉及位置**：`PartDataImportPanel.vue`、`src/components/import/`、`importDiagnostics.ts`、`partDataImportV2.ts`、`childClaim.ts`。
- **验收**：筛选/分页/切换 Tab 不丢本次决定；撤销后统计与预览一致；无候选仍可保留原始声明；确认不会改名、覆盖生父或自动合并人物。
- **依赖**：M1-01。刷新浏览器后的草稿恢复不默认包含在首版，关闭前应明确提示未保存状态。

### M1-04 核对结果的精确提交与批次追踪

- **目标**：云端保存的必须是用户核对过的结果，而非重新解析产生的另一份结果。
- **拆分任务**：替换当前仅凭原始文本再次解析的确认路径；提交经共享契约校验的核对快照及决定；绑定预览时的基线修订号；保存批次摘要并提供结果页。
- **异常场景**：核对期间别人更新数据、确认重复点击、服务端拒绝、请求已提交但响应丢失；采用可核实的操作标识与状态查询，不能自动重复覆盖。
- **数据边界**：人工核对不能绕过循环、引用、重复 ID 校验；重新上传或重新解析时旧决定必须重新校验，不按临时 ID 盲目复用。
- **验收**：修改一条候选后导入，云端与预览逐字段一致；保存失败保留核对结果；响应丢失时可确认真实提交状态；批次可关联对应审计。
- **依赖**：M1-02、M1-03。

### M1-05 删除影响预览

- **目标与入口**：成员删除确认前，明确显示整个删除范围及关联影响。
- **拆分任务**：展示目标和后代名单、事件数量、配偶/声明/关系影响、轨迹解除关联数量；支持查看完整名单；确认按钮使用明确数量和动作文案。
- **行为边界**：首版保持现有删除成员及其后代语义，不自行改成“只删本人”或软删除；轨迹保留，剩余关联成员顺序不变。
- **涉及位置**：`MemberManager.vue`、`familyStore.ts` 及共享影响计算；预览与执行复用同一规则，基线过期必须重新预览。
- **验收**：预览数量与执行结果一致；取消不写入；并发修改使旧确认失效；失败完整回滚；不存在悬挂引用。用含多配偶、承继、事件和多成员轨迹的样例验证。
- **依赖**：M0-03、M1-02。回收站和自动撤销另行立项。

### M1-06 导入覆盖与备份恢复差异预览

- **目标与入口**：恢复或导入前，不仅展示文件中有多少数据，还显示对当前数据的影响。
- **拆分任务**：按集合列出新增/删除/变更数量与可展开明细；显示备份 schema、格式和可得的生成信息；提供当前数据导出入口；确认时绑定预览基线。
- **两类语义**：完整备份恢复替换业务快照；Markdown 导入替换谱系相关集合，保留事件和轨迹但清空旧人物关联。界面分别说明，不能混用一套“全部恢复”文案。
- **匹配边界**：完整备份可按 ID 比较；不同来源 Markdown 不凭同名或恰好相同的 ID 宣称是同一人物，无法可靠映射时展示替换范围而非伪造字段差异。
- **验收**：合法空备份、旧 schema、未知版本、坏引用、完整九集合以及有序轨迹关联均有场景；取消或失败不改变原数据；过期预览不能直接提交；账号/会话不受业务恢复影响。
- **依赖**：M1-02、M0-03。自动备份留存策略见 M4-05，不假定已存在服务端历史版本。

### M1-07 并发冲突处理闭环

- **目标与入口**：保存冲突后，用户知道别人改了什么，并能保留自己的编辑意图。
- **拆分任务**：保存编辑基线、当前表单草稿及新云端数据；展示字段差异；提供重新加载后重填、复制草稿、针对明确字段重新应用并再次确认。
- **首版范围**：优先成员普通字段编辑；父子/承继关系、批量导入、删除和整库恢复发生冲突时，要求重新预览及确认，不自动合并。
- **实现边界**：最终仍使用最新修订号 CAS；“重试”不能把原快照改上新修订号强行覆盖；网络超时与明确的修订冲突分开处理。
- **验收**：两个维护者编辑同一人与不同人、远端已删除对象、冲突后再次发生冲突、会话失效均可解释并保留合理输入；没有强制覆盖默认按钮。
- **依赖**：M1-01、M1-02、M0-06。

## 5. M2：查谱与导出体验

### M2-01 本人档案绑定

- **目标与入口**：账号菜单可设置“我的族谱档案”，总览提供稳定的本人入口。
- **拆分任务**：搜索候选并展示身份区分信息；选择后再次确认；支持解绑与更换；目标不存在或被删除时显示失效提示。
- **决策边界**：首版建议作为个人浏览偏好，不作为本人身份认证、权限提升或数据所有权证明；若要求唯一认领或管理员审核，先走 G-01 决策。
- **数据变更**：绑定属于账号配置，不放入可分享的族谱业务备份；Markdown 替换和备份恢复可能复用 ID，必须显式使绑定失效或安全重核，不能悄悄指向同 ID 的另一个人。
- **验收**：同名候选不自动绑定；账号切换不继承绑定；只读用户绑定后仍无写权限；删除、重导入和恢复后不会误指认本人。
- **依赖**：M0-03、G-01。

### M2-02 定位到我与常用人物

- **目标与入口**：总览提供“定位到我”和常用人物列表，减少反复搜索。
- **拆分任务**：绑定有效时定位并展开必要祖先路径；与当前筛选冲突时明确提示并允许调整；支持添加/移除常用人物；处理被删除或失效的收藏。
- **行为边界**：不重置不相关分支的折叠状态；不根据手机号、同名或首次访问自动选定本人；无绑定时提供设置入口。
- **数据变更**：常用人物按账号隔离；适用 M2-01 的数据替换失效规则；存储位置、数量上限在实施前确认，不默认无限增长。
- **验收**：隐藏于折叠分支、被筛选排除、手机与桌面切换时均能解释定位结果；退出后不残留上一账号的常用列表。
- **依赖**：M2-01、M0-04。

### M2-03 父系路径与共同祖先查询

- **目标与入口**：档案中“查看祖先路径”；总览中选择两人查询共同祖先。
- **拆分任务**：展示本人到已记录祖先的有序路径；显示最近共同祖先及两侧路径；节点可跳转档案；提供树图路径高亮与清除。
- **语义边界**：首版只用已记录生父链，明确标注“父系范围”；承继、配偶、未匹配声明不混入；没有共同祖先记录不等于不存在亲属关系。
- **涉及位置**：`treeBuilder.ts`、`treeView.ts`、`MemberArchive.vue`、`FamilyWorkspace.vue`；优先复用现有关系校验与索引。
- **验收**：同一人、父子、兄弟、跨代旁支、不同根、父亲未录、无效 ID、异常循环均有用例；不把谱载代数当成树深度；不输出缺乏依据的亲属称谓。
- **依赖**：M0-03。

### M2-04 受控 CSV 名录导出

- **目标与入口**：名录按当前筛选条件导出，供核对和整理。
- **拆分任务**：选择允许的字段；预览条数及导出范围；支持全部筛选结果而非仅当前页；包含稳定可读的列名、人物 ID、姓名、分支、代数和经授权字段。
- **安全与格式**：处理逗号、换行、引号、中文编码及公式型单元格；未知值留空并保持语义；默认不导出手机号、账号信息、精确坐标或隐藏字段。
- **实现边界**：CSV 是可读名录，不是完整可恢复备份；导出权限同时约束数据读取，不能只隐藏按钮；大数据量导出给出进度与取消。
- **验收**：筛选条数与导出条数一致；常用表格软件打开中文正常；换行和公式前缀样例安全可读；取消不输出半份误导性文件。
- **依赖**：G-02、M0-03。

### M2-05 人物档案与分支打印/PDF

- **目标与入口**：人物档案打印、选定分支打印，服务线下查谱和家庭分享。
- **拆分任务**：先做浏览器打印版式和“另存为 PDF”说明；提供 A4 纵向档案、横向分支视图；标示标题、范围、生成日期、页码和必要的不确定性说明。
- **范围控制**：超大树按分支/代际分页，不把全谱压成无法阅读的一张图；优先矢量或清晰文本，不把现有 PNG 下载称为 PDF。
- **权限与异常**：遵守 G-02 字段范围；照片不可用时保留版式；字体和长姓名不能截断；不依赖外部服务上传谱文转换。
- **验收**：小分支、跨页大分支、长生平、多配偶和缺失日期样例可读；中文无缺字、节点不重叠、分页不丢内容；打印取消不改变数据。
- **依赖**：G-02、M0-04。直接生成 PDF 文件仅在打印版式通过后另评估，不默认增加重型库。

### M2-06 浏览效率与无障碍完善

- **目标与入口**：总览、名录、档案和查询结果保持一致的导航体验。
- **拆分任务**：明确空列表、无搜索结果和加载失败三类状态；保留返回名录后的筛选和位置；补键盘焦点顺序、弹窗焦点恢复、按钮标签、图谱文本替代入口。
- **移动场景**：过滤条件折叠但保留当前条件摘要；加载更多按钮与自动加载并存；新增路径查询和导出入口不挤压现有顶栏。
- **涉及位置**：`FamilyWorkspace.vue`、`MemberArchive.vue`、`MemberCardList.vue`、相关管理组件。
- **验收**：不使用鼠标可完成查找、打开档案和关闭弹窗；读屏能识别主要操作；仅颜色高亮之外有文字反馈；大字号下无操作丢失。
- **依赖**：M0-04；新功能入口随 M2 各任务完成后逐项纳入。

## 6. M3：档案与寻根增强

### M3-01 生卒与籍贯信息维护

- **目标与入口**：族人编辑表单可维护死亡信息、籍贯及其原始记载。
- **拆分任务**：先统一现有 `birthDate` 与 `temporals` 的读取优先级；设计生卒字段/纪年表达的编辑入口；区分籍贯、出生地、葬地；显示来源与不确定状态。
- **数据原则**：原始纪年、标准日期、日期精度分别保存；只有年份不得补造月日；缺少卒日不等于在世；标准化结果不能覆盖原文。
- **数据变更**：明确 `Member` 与 `TemporalExpression` 的唯一写入规则，避免重复存储矛盾；补前后端校验、D1 迁移、旧数据迁移和两种备份往返。
- **验收**：公历完整日期、仅年、传统纪年、相互冲突与未知信息可正确录入显示；出生晚于死亡等矛盾有明确反馈；取消不改旧值。
- **依赖**：M1-01、M1-02。

### M3-02 人物生命时间线

- **目标与入口**：人物档案把生卒、已记录事件及相关资料按可解释的顺序展示。
- **拆分任务**：聚合现有事件与纪年；显示来源及精度；允许跳转原事件；同日稳定排序；未知日期单独分区。
- **语义边界**：不能可靠换算的传统纪年保留原文，不混入精确公历排序；同一事实在成员字段和事件中同时存在时，定义去重或并列说明规则。
- **涉及位置**：`MemberArchive.vue`、事件服务、纪年展示辅助逻辑；避免新建一套脱离现有事件的时间线数据。
- **验收**：日期不完整、事件无关联、并列事件、删除事件、资料冲突均正确显示；计算年龄时尊重精度，不显示伪精确数字。
- **依赖**：M3-01。

### M3-03 GPX 轨迹地图预览

- **目标与入口**：事件与轨迹页及只读总览可查看轨迹线、起终点、距离和有序关联族人。
- **拆分任务**：按需加载地图；自动适配轨迹范围；显示起终点；允许从轨迹进入族人档案；处理大点数轨迹的展示简化与取消加载。
- **关键边界**：关联成员顺序不是途经坐标，不伪造墓位或途经点；简化仅影响显示，不能改写原 GPX 点序列和备份。
- **外部依赖**：地图提供方、授权、费用、坐标系和隐私提示由 G-03 决定；未经选择与授权，不向第三方上传原始 GPX 或个人资料。
- **验收**：短线、跨区域、重复点、大点数、坐标转换和地图不可用场景有覆盖；地图失败仍保留列表、轨迹统计和既有终点导航。
- **依赖**：G-03、G-02、M0-04。

### M3-04 生卒与世代高级筛选

- **目标与入口**：总览和维护名录使用一致的筛选规则定位人群。
- **拆分任务**：增加谱载代数区间、出生年份区间、资料完整度及明确记录的生存状态筛选；显示条件摘要、结果计数与一键清除。
- **语义边界**：谱载代数与相对树层级分开；未知年份/状态有独立选项；无卒日不能自动归类为在世；不要以人物年龄推断死亡。
- **数据与复用**：筛选规则抽取为可测试的共享纯逻辑；现有分支/性别/姓名搜索保持兼容；CSV 使用同一结果集。
- **验收**：多条件交集、未知值、边界年份、无结果、刷新数据后页码和移动追加数量均正确；查询与导出数量一致。
- **依赖**：M3-01；与 CSV 联动验收依赖 M2-04。

### M3-05 配偶与承继局部关系视图（可选）

- **目标与入口**：人物档案中查看有限范围的配偶、生父、承继父及子女关系，不立即改变全谱主树。
- **拆分任务**：先定义关系图例和范围；区分实线、虚线及不确定状态；提供关系来源查看；多配偶和多种父系角色分别呈现。
- **模型边界**：现有 `Spouse` 记录不一定是一个独立 `Member`，不能直接把配偶记录 ID 当成员 ID；没有关联档案时只展示配偶资料，不生成虚假族人。
- **范围控制**：只展示选中人物的局部关系；以 ECharts 现有能力优先验证，不为了本项替换全谱引擎；不绘制未经确认的声明为确定关系。
- **验收**：生父和承继父并存、多配偶、无独立配偶档案、关系不确定及局部无数据样例可读；手机不重叠；父系主树既有行为不变。
- **依赖**：M1-01、M2-03；纳入本轮与否须单独确认。

## 7. M4：规模化与协作（按条件启动，基础恢复除外）

### M4-01 建立性能与容量基线

- **目标**：用证据决定优化方向，不以主观流畅度或人数阈值代替测量。
- **拆分任务**：生成无真实个人信息的 1,000 / 5,000 / 10,000 人样例，覆盖宽树、深树、多分支；分别加入短轨迹和高点数轨迹；记录请求大小、SQL 数量、加载/保存耗时、主线程阻塞和图谱展开耗时。
- **测量规则**：固定设备、浏览器、网络与可见节点数量，区分冷启动和热运行；重复测量报告中位数与 P95，不只保留最好的一次。
- **建议目标，待实测确认**：5,000 人数据、可见节点不超过 200 时，桌面搜索反馈 P95 不超过 300ms、展开反馈 P95 不超过 500ms；普通手机首次可交互不超过 5s，须同时记录网络和载荷。
- **验收**：形成可重复运行的基线和瓶颈归因；对超标项给出测量结果，而不是通过削减数据或隐藏错误声称达标。指标是规划目标，不是当前性能承诺。
- **依赖**：无，可在 M0 后提前执行；不是必须等 M3 完成。

### M4-02 按瓶颈引入增量保存与分层加载

- **启动条件**：M4-01 证明全量保存、轨迹载荷或图谱计算导致指标超标。
- **拆分任务**：先做低风险索引/缓存/重复计算优化；必要时再拆成员普通字段更新和轨迹读写；为新接口定义修订、幂等和权限语义；兼容旧客户端与备份快照。
- **一致性边界**：局部更新和整库恢复必须共用明确的并发规则；不能让旧全量 PUT 覆盖新局部修改；迁移期间不得出现两套相互失效的审计和权限。
- **涉及位置**：`api/index.ts`、`d1ApiService.ts`、`familyStore.ts`、图谱服务；只优化已证明的瓶颈，不预建无需求架构。
- **验收**：相同样例下报告前后差异；满足约定指标；旧备份仍可读；成员删除、导入、审计、并发回归保持正确。
- **依赖**：M4-01、M1-02、M1-07。

### M4-03 成员修改提议与审核

- **目标与入口**：普通成员可提交更正建议，维护者审核后才改变正式族谱。
- **拆分任务**：限定首版可提议的字段；保存建议值、原值、理由及基线；提供待审核队列、详情对比、通过/驳回/撤回；让提议者查看自己的处理状态。
- **范围控制**：首版不允许普通成员直接执行删除、整库导入、人物合并或关系改写；不默认加入邮件/短信通知。
- **数据与权限**：提议存服务端独立集合；服务端校验提交和审核角色；审核时重新检查目标、版本和当前权限，禁止直接覆盖已经变化的数据。
- **验收**：普通用户无法绕过审核写主数据；重复审核不重复生效；成员删除、权限变化、基线过期、本人撤回与审核竞争均有明确结果；通过操作进入审计。
- **依赖**：G-01、G-02、M1-02、M1-07；是否允许审核自己的提议需先确认。

### M4-04 只读 PWA 与受控缓存

- **启动条件**：用户明确需要安装或离线查阅，并确认离线资料的隐私取舍。
- **拆分任务**：第一步仅做安装入口和静态应用壳缓存；第二步经确认后缓存允许的只读资料；显示缓存时间、离线状态、更新提示和清除入口。
- **边界**：不开放离线新增/编辑/导入；不同账号缓存隔离；token、账号管理响应和未授权字段不进入通用缓存；静态资源版本切换不能造成前后端契约错配。
- **风险决策**：断网期间无法实时知道账号已禁用，必须明确缓存有效期和重新联网验证策略；不能声称“退出清理”解决了所有远程撤权问题。
- **验收**：首次无网络、已缓存离线、版本升级、退出登录、换账号、缓存过期和重新联网均有场景；在线失败不自动变成可编辑本地副本。
- **依赖**：G-01、G-02、M0-06、M4-01；只读资料缓存需要独立批准，不能随应用壳一起默认启用。

### M4-05 运营备份与恢复演练（基础 P0，规模化 P2）

- **目标**：把手动文件备份补充为可管理、可核验的恢复能力。
- **优先级拆分**：基础备份、失败告警、隔离恢复和负责人在 M0 交付，是首次真实资料上线的门槛；本项后续补批量运营、保留策略自动化与规模化恢复，不得理解为全部备份能力均可延后。
- **拆分任务**：定义业务快照和基础设施级备份的用途；确定频率、存放位置、访问控制、保留期、失败告警与恢复负责人；设计校验摘要和隔离环境恢复演练。
- **边界**：业务文件仍不含账号/会话；若需要整库恢复，采用单独的受控流程；自动备份不等于自动覆盖生产恢复。
- **运行决策**：先确认恢复点目标和恢复时长目标，再选择平台能力或定时任务；不在当前会话自动创建定时任务、外部存储或收费服务。
- **验收**：指定备份可恢复到隔离库，业务集合、关系、轨迹顺序和计数器一致；损坏备份被拒绝；过期删除及失败告警可验证；记录实际恢复耗时。
- **依赖**：规模化部分依赖 M0-05、M1-06、G-02；基础恢复按 M0-05 独立完成，不等待差异预览 UI。保留成本和恢复目标需确认。

## 8. G：实施前必须确认的决策

以下是待确认项，不构成用户已经批准的产品变更。可以先做不依赖决策的 M0 工作，但接收真实个人资料前必须完成适用的身份、授权与隐私实施，不能只完成决策记录。

### G-01 身份验证与档案绑定策略

- **已有基线**：v0.1.7 全角色独立密码、受限改密会话、凭证版本与撤销、认证限流已实现；正常会话默认 24 小时、受限会话 15 分钟。手机号只是账号标识，没有短信验证或公开自助找回。
- **需要决定**：公网/更多维护者的适用范围；是否需要额外加强验证；绑定是浏览偏好还是需审核的本人认领；实际会话配置、凭据交付与线下身份确认、管理员恢复及过渡退出责任。
- **建议方向**：复用现有独立密码方案，不重复从零建设或默认采购短信；核验存量升级、人员撤权及旧入口关闭。个人偏好绑定不能带来额外权限，密码验证不代替本人认领或资料授权。
- **交付物**：角色与登录方式矩阵、v0.1.7 账号迁移和强制改密验收记录、临时密码私密交付与账号恢复路径、服务端验收用例；额外认证仅在确认需求后安排。
- **阻塞范围**：真实资料上线，以及 M2-01、M4-03、M4-04、所有客户托管。基础身份控制仍为 P0，已有实现不等于部署与运营验收完成；剩余决策与证据补齐后才解除相应阻塞。

### G-02 隐私、导出与审计访问规则

- **需要决定**：在世成员资料、生卒细节、照片、葬地坐标的各角色可见范围；普通用户能否导出；审计能否查看字段正文；审计与运营备份的保留期。
- **建议方向**：字段最小可见、导出显式授权；登录凭据和会话永不进入业务导出；不能只依靠前端隐藏已经下发的敏感字段。
- **交付物**：字段 × 角色 × 场景（在线查看/导出/离线/审计）的权限矩阵；后端过滤与恢复完整性的协调方案。
- **阻塞范围**：真实资料处理与开放、M1-02、M2-04、M2-05、M3-03、M4-03～M4-05；基础授权规则先落实，复杂字段策略可以按需求分期，不能把本计划的建议默认当作现有权限。

### G-03 地图提供方与坐标策略

- **需要决定**：目标使用地区、地图服务商、底图授权、费用、Key 限制、坐标转换、网络失败降级及第三方请求告知。
- **建议方向**：保留原始 GPX 坐标与点序列；显示转换不回写源数据；地图模块按需加载；无明确需求不上传 GPX 文件到第三方。
- **交付物**：服务选择说明、坐标系样例验证、访问限制及隐私说明。
- **阻塞范围**：M3-03；在此之前可独立设计不依赖提供方的轨迹详情布局。

## 9. 数据、接口与迁移的统一约束

### 9.1 每次数据变更的检查清单

- [ ] 明确业务字段、账号偏好、审计、提议、缓存分别归属，避免全部混入 `FamilyData`。
- [ ] 同步更新类型、共享校验、Worker 读写、store、表单、展示与相关查询。
- [ ] 新持久化业务字段确有需要时升级 schema；定义旧版本迁移与不支持版本的显式错误。
- [ ] JSON/SQLite 对纳入业务备份范围的字段完整往返；旧备份缺失的新增字段有明确语义。
- [ ] D1 增量迁移保留既有数据，覆盖空库、旧库、已自动升级库和重复部署。
- [ ] 普通写入、Markdown 导入、恢复、删除均遵守修订号与引用完整性规则。
- [ ] 批量替换数据时处理账号绑定、常用人物、待审核提议等外部引用，不依赖可复用的数字 ID 猜测人物身份。
- [ ] 服务端负责身份、权限、校验、审计；客户端的预览与按钮状态不能替代服务端判断。
- [ ] 明确新旧客户端同时在线时的行为；不支持的旧写入应明确拒绝，不能静默丢字段。

### 9.2 高风险操作的统一交互

1. 读取当前数据及修订号，生成可解释的影响预览。
2. 用户确认准确范围；取消不产生业务写入。
3. 服务端检查权限、格式、引用、修订号和操作身份，事务提交。
4. 只在确认提交成功后显示成功并清理草稿。
5. 已知失败保持原数据和可恢复输入；结果不确定时核实操作状态，不盲目重放。
6. 保存成功后刷新相关视图、外部引用和审计；失败不记录为成功。

## 12. 18～24 个月长期路线

### 12.1 产品定位与付费对象

长期定位建议为：**面向家族维护者的可信数字族谱与持续维护服务**，而不是追求高日活的家族社交平台。

核心价值是“资料不丢、关系有依据、后人能接手、族人容易查阅”。使用者与付款者可能不同：多数普通族人负责浏览，维护者、修谱负责人或有预算的家族组织承担维护和付费。首发进一步聚焦为**有明确资料负责人、较清晰电子谱文、近期有成果交付需求且能协调关系核对**的客户假设，不同时服务下面全部人群。

先验证一个购买触发与可验收成果。客户只要电子文件或打印成果时，不默认推销持续托管。授权不明、无人确认疑点、低价全自动处理模糊扫描、无限返工或首单复杂平台定制等需求建议首期不服务，具体接单边界仍待确认。以下是候选细分，不是已确认客户：

| 人群 | 主要问题 | 可付费价值 | 前期优先度 |
| --- | --- | --- | --- |
| 已有电子文档的家族维护者 | 导入麻烦、关系容易错、亲属不方便看 | 导入核对、托管、备份、多人维护 | 最高，最接近当前能力 |
| 持有纸质族谱的修谱负责人 | 资料分散，录入和校对工作量大 | 有范围约定的数字化整理、校对与成果交付 | 后续单独验证，首期不默认接复杂扫描；不能承诺现有 OCR 可用 |
| 多人协作的家族组织 | 账号交接、审核、档案延续 | 权限、审计、交接和恢复演练 | 中期，需要更完整治理能力 |
| 普通家族成员 | 查祖先、看家族事件和资料 | 受邀浏览、查询、提交更正 | 主要使用者，不建议首期逐人收费 |
| 专业修谱或印刷合作方 | 多个项目整理与交付 | 项目管理、批量核对、导出排版 | 后期验证，避免过早多租户和定制化 |

| 6～12 个月：产品化复用 | L-01 档案库、L-02 修谱项目、L-03 协作交接中择需推进；完善 M4 | 固定服务边界、建立标准套餐和成本台账；小规模转介绍和合作方试点 | 有重复使用或持续维护证据；支持负担可承受；新项目多数步骤可复用而非重做 |
| 12～18 个月：验证续费 | 有需求才做 L-04 多家族平台；评估 L-05 专业排版 | 观察到期客户真实续费；必要时建设支付与订阅自动化 | 付费队列达到足以判断的规模；续费理由明确；故障恢复、数据迁出和客户交接可靠 |
| 18～24 个月：有选择地扩展 | 从 L-06 OCR、L-07 离线、L-08 数据互通中最多先选一个 | 扩展有效渠道或机构合作，优化单位经济性 | 新方向有明确需求和付费验证，不损害基础产品可靠性与交付能力 |

人数是实验规模而非通过阈值或销量预测。每个访谈批次、小样和订单结束就评审，资源上限到达即暂停新增投入；阶段现金/人力上限与允许重试尚待批准。小样本报告分子、分母和拒绝理由，不用百分比宣称市场已验证，不等两个季度才停止，也不按月份自动升级架构。

### 12.3 三种可接受的长期结果

- **个人/家族工具**：真实使用但付费需求弱时，继续维护稳定版本、导出和迁移，不为商业化增加不必要复杂度。
- **小规模服务业务**：客户愿为整理和托管付费，但不需要平台化时，保持少量隔离实例和标准服务，不强行做 SaaS。
- **可复制的订阅产品**：只有在重复获客、支持成本、持续使用和续费成立后，才投资多家族平台、账单自动化与渠道扩展。

商业化不是项目成功的唯一标准。保留用户数据可迁出和项目可长期维护，比为了短期收入锁住资料更重要。

## 13. 变现路径与定价实验

### 13.1 可行性判断

**建议有条件验证明确成果的数据整理服务，尚不足以批准完整商业执行或固定团队。** 当前基础值得验证，但身份、授权、安全交付、恢复、合同与成本未完成验收。客户可能只买文件或打印成果；整理成交不证明托管需求。小规模托管需要独立的客户、价格与运营验证，而非默认附加收入。

族谱查阅可能是低频行为，基础软件本身也存在免费或自建替代。收入假设应建立在省去的整理时间、持续维护责任和可信交付上，而不是假定每个家族成员都会买会员。

仓库根目录为 MIT 许可，Vben 本地来源记录亦标注 MIT，这支持评估商业使用，但仍需遵守许可声明并逐项检查依赖、字体、地图、图片和客户资料的使用权。开放源码不是商业壁垒：应主要靠核对质量、服务流程、可恢复性和长期信任，而非尝试撤回已授予的开源权利。

### 13.2 建议收入结构

| 方式 | 交付内容 | 建议启动时点 | 主要成本或风险 |
| --- | --- | --- | --- |
| 一次性资料整理 | 约定范围的电子文本清理、导入、人工核对清单、客户确认、完整备份与培训 | 商业前置条件就绪后优先试点 | 文档差异大，人工工时易失控；不承诺无法证实的族谱正确性 |
| 年度托管与维护 | 私有访问、版本维护、约定的备份与恢复支持、有限额的日常技术支持 | 有付费试点且 B-04 验收后 | 支持和运维可能超过基础设施成本；必须明确范围和期限 |
| 定制排版/打印交付 | 指定分支或修谱版本的排版文件；印刷另报价 | M2-05 验收后，复杂排版依赖 L-05 | 校样反复、字体授权、印刷质量与物流售后 |
| 专用部署/迁移服务 | 部署到客户同意的环境，配置、迁移、培训与约定支持 | 客户明确有此需求时 | 环境差异和长期维护责任；不能用低价一次性交付承诺终身运维 |
| 专业机构合作 | 多项目管理、核对与排版协作、可追溯交付 | 已有可复制流程后 | 定制范围、资料授权、结算周期、合作方质量 |

**不推荐的收入方式**：出售或出租族谱个人信息、定向广告追踪、将客户资料用于未授权训练、强迫用户付费才能拿回原始资料、承诺“永久托管”。不靠按人物记录数量突然封锁历史资料来迫使续费。

### 13.3 首轮报价假设

以下金额为人民币实验区间，只用于访谈和试点报价设计；未核验市场价格、税费、服务商费率或客户接受度。正式报价必须写明服务期限、数量、工作量、税费处理和超范围规则。

| 实验产品 | 初始价格假设 | 必须限定的交付范围 | 不包含 |
| --- | --- | --- | --- |
| 自建基础使用 | 软件按现有 MIT 许可提供 | 自行部署与社区文档；可另售安装支持 | 免费代部署、无限客服或托管承诺 |
| 家族托管基础档 | 299～699 元/家族/年 | 一个隔离家族实例；试点示例为至多 3 位维护者、约定存储额度与工作时段支持；额度经实测确定 | 大批量人工录入、无限附件、复杂定制 |
| 电子资料导入整理 | 999～2,999 元/项目起，先小样评估 | 示例试单为不超过 300 条清晰电子文本记录、至多 2 轮核对反馈；复杂度或规模变化重新报价 | 默认包含扫描、全文 OCR、历史考据或无限返工 |
| 档案/分支排版文件 | 299～999 元/次 | 指定版式、页数范围和至多 2 轮校样；客户签字或明确确认定稿 | 印刷、快递、无限页数、定稿后的无限修改 |
| 专用部署与培训 | 1,999 元/项目起，按环境核算 | 一次部署、一次迁移和约定培训；后续支持单独订约 | 云资源费用、全天候响应、永久免费升级 |

套餐中的名额、存储和反馈轮次只是实验边界，不是已经批准的产品限制。若增加限制，优先限制新增资源并提供清理/升级路径，不突然阻断已有数据查看和迁出。托管到期后的只读期限、导出窗口和最终删除规则必须事先约定，不能无限期承担免费托管，也不能立即删除资料。

以每小时 100 元的占位劳动成本，999 元在 9.99 小时、2,999 元在 29.99 小时即全部消耗于劳动，尚未扣其他成本；399 元年费中的 2 小时支持已消耗 200 元。记录量和两轮反馈不等于工时可控：先用获准小样覆盖源文质量、同名、承继、缺失和客户协调，再估算售前、核对、返工、复核、培训、售后与退出工时。报价不是这些区间的自动套用。

### 13.4 定价验证方法

1. 先访谈当前整理方式、投入工时、决策人和预算来源，再展示方案，避免只问“你觉得值多少钱”。
2. 用匿名演示或获授权的小样展示具体交付，询问是否愿意进入有范围、有价格的试点。
3. 不对同一客户隐藏改变条件；每次实验明确比较的是价格、服务范围还是付款方式。
4. 分开记录咨询、接受报价、实际付款、完整交付、退款、后续使用和续费，不把口头兴趣算成交。
5. 收费能力或合规前提尚未就绪时，只做访谈与意向确认，不收款、不承诺尚未能交付的服务。

## 14. L：长期产品能力拆分

### L-01 家族资料库与来源引用

- **价值**：让人物记录可追溯到获授权的谱页、照片或文档，支持后续核对与交接。
- **拆分任务**：文件上传与类型/大小限制；对象存储和访问鉴权；资料来源、页码/位置与成员关系；缩略图与按需加载；授权与删除记录。
- **关键边界**：照片 URL 不等于受管理的附件；附件需要独立备份、迁出和费用核算。业务快照包含引用时，必须明确是否同时导出文件包及完整性清单。
- **验收**：未授权用户不能取文件；删除、重导入和恢复不会留下错误关联；原文件与引用可核验迁出；恶意或损坏文件显式拒绝。
- **依赖/启动条件**：M1-01、G-02、B-03；至少有试点明确需要来源资料，不提前建设无限量云盘。

### L-02 修谱项目与版本发布

- **价值**：区分持续编辑中的资料与已经校对发布的修谱版本。
- **拆分任务**：项目范围、责任人与任务清单；草稿/待核对/已发布状态；版本差异；发布确认与不可变版本标识；关联排版产物和备份。
- **关键边界**：发布版与当前业务修订号不同；不得用旧发布版直接覆盖线上数据；修订历史的容量与保留期需要控制。
- **验收**：能从一个版本追溯来源、核对记录和批准人；发布后修改生成新版本；导出可以明确选择当前数据或某个已发布版本。
- **依赖/启动条件**：M1 核对与审计闭环；有跨月整理、多人校对或定期修谱需求。

### L-03 家族治理与维护者交接

- **价值**：降低资料依赖某一个维护者的风险，让后续成员可以继续维护。
- **拆分任务**：区分平台运营身份与家族内部管理员；维护者邀请和撤权；待交接事项、未审提议与备份交接；账号恢复与所有权转交确认流程。
- **关键边界**：没有授权不得替客户转交资料；转交过程防止无人管理和原管理员继续访问；付费联系人、管理员和资料权利人不必是同一人。
- **验收**：交接前后权限矩阵明确；原权限及时撤销；审计和恢复入口保留；争议、联系人失联有人工处理流程而不是自动转给任意申请者。
- **依赖/启动条件**：G-01、G-02、M1-02、M4-03；试点证明存在多人维护与延续需求。

### L-04 多家族平台与租户隔离

- **价值**：只有当隔离实例运营成本明显成为瓶颈时，才用平台化降低交付成本。
- **拆分任务**：明确家族空间和成员归属；为查询、写入、文件、审计、备份、导出及队列全部建立租户边界；租户级容量与停用；从独立实例迁入和迁出的工具。
- **关键边界**：不能只给前端加“切换家族”按钮或给少量表补 `tenantId`；同一账号跨家族时角色、数据和缓存必须分别计算。
- **验收**：覆盖跨租户 ID、文件链接、批量导入、后台任务和管理员操作的隔离测试；能单独恢复/导出一个家族；任何跨租户泄露均为发布阻断。
- **依赖/启动条件**：B-04 已验证隔离运营、B-08 有成本证据、M4-01 有容量证据、L-03 明确管理员边界。客户数量只是参考，不是自动启动理由。

### L-05 专业修谱排版与印刷交付

- **价值**：把通用打印升级为明确版本、可校样、可交付的修谱成果。
- **拆分任务**：有限模板、目录与索引、世代/分支分册、页码和版心；草稿水印、校样记录、最终确认；合作印刷文件规范。
- **关键边界**：不与 M2-05 的基础打印重复收费含糊不清；专业排版收费对应额外模板、人工校样或特定输出，不撤回基础导出。
- **验收**：复杂中文姓名、跨页关系、多配偶和原文注释正确；定稿版本可重现；客户确认、印刷质量和物流责任分别约定。
- **依赖/启动条件**：M2-05、L-02、B-02、B-03；已有客户愿意为明确排版成果付款。

### L-06 经核对的 OCR 辅助录入（明确重启后）

- **价值**：减少机械录入时间，不代替人工认定家族关系。
- **拆分任务**：使用获授权样本建立字级、姓名级、字段级与关系级评估；先识别再进入 M1 核对工作台；保存来源位置、置信信息和模型版本；提供成本与失败反馈。
- **关键边界**：继续保留“暂缓”默认状态，重启需明确决定；不得把实验组件直接视为产品；云 OCR 需数据处理授权和费用上限。
- **验收**：与纯人工录入比较实际节省工时及漏错情况；关键关系错误仍需逐项确认；供应商失败、缺字与低置信结果不会自动写入正式族谱。
- **依赖/启动条件**：L-01、M1-03、M1-04、B-03；实际付费订单证明录入是主要成本，再确认重启。

### L-07 离线采集与受控同步（可选）

- **价值**：服务弱网走访、实地资料采集，区别于 M4-04 的只读缓存。
- **拆分任务**：先做独立待提交采集草稿；客户端唯一标识、重试幂等、待上传附件；联网重新验证身份；同步冲突预览和人工解决；明确设备丢失处理。
- **关键边界**：首版不允许离线删除正式成员、整库恢复或改写关键亲属关系；服务端权威与权限检查不因离线而绕过。
- **验收**：长时间断网、账号被禁用、重复同步、远端对象删除、附件部分上传与本地空间不足均有明确恢复路径；不出现静默覆盖或假成功。
- **依赖/启动条件**：M1-07、M4-04、G-01、G-02；有明确走访频率和支付意愿，否则维持在线编辑。

### L-08 标准格式互通与数据迁出

- **价值**：减少客户对供应商锁定的担忧，并支持专业工具之间迁移。
- **拆分任务**：调研目标格式版本和真实样例，例如 GEDCOM；建立字段映射、损失报告和导入预览；导出可读资料、关系、附件清单与必要的原文。
- **关键边界**：外部格式未必能表达承继、谱载代数、子女声明和全部不确定性；不能把“可导出”宣传为无损双向互通。
- **验收**：已支持字段可往返；不能映射的字段显式提示并保留可迁出的原始补充文件；用户终止服务时也能完成约定的资料交接。
- **依赖/启动条件**：M1-01、B-03；具体格式支持按真实迁移需求选定，不建设没有使用方的通用连接平台。

## 15. B：商业验证与运营工作包

### B-01 需求访谈与付费主体确认

- **拆分任务**：先聚焦一个首发画像、近期购买触发和具体成果；8～12 位访谈是规模参考，不要求同时覆盖所有人群。了解现有格式、替代方案、工时、预算、决定权、疑点协调和不适合服务的需求。
- **交付物**：脱敏需求分类、现有替代方式、最小付费场景、被拒绝理由；不把受访人的真实家谱上传到公共仓库或分析服务。
- **验收**：有具体成果的购买意愿、实际负责人和合理成本提案的证据；只有兴趣、无人确认疑点或没有近期触发时立即收窄/转向，不以完成访谈数通过。
- **依赖**：无，可与 M0 并行；访谈记录仅按获准目的最小化保留。

### B-02 服务产品与交付边界

- **拆分任务**：定义一个可验收成果的输入版本、授权、疑点、客户确认、交付格式与退出方式；明确不服务范围、工时预算、反馈轮次、超范围处理和售后；托管另验证。
- **交付物**：小样评估表、成果确认单、报价、变更与验收模板；首期必做/受控人工/延期范围表及未决规则；“数据整理”不承诺“历史考据”。
- **验收**：客户清楚买到的成果、不包含什么、如何确认和迁出；核对结果与交付一致，全部工时可记录；人工替代先复核验收，不能因少建 UI 省去数据安全。
- **依赖**：B-01；定价必须由项目负责人确认后对外使用。

### B-03 数据授权、合同、许可与退出机制

- **拆分任务**：确认运营主体与目标服务地区；制定服务条款、隐私说明、资料处理授权、退款和到期处理；核验依赖、字体和地图许可；确认开票/税务/支付渠道要求。
- **关键边界**：上传者应确认有权委托处理，但这不自动代表取得了所有在世成员或未成年人的同意；需按适用规则评估合法基础与权利请求处理。涉及个人信息处理、跨境托管等问题应寻求合适的专业意见。
- **交付物**：资料可用于什么、可由谁访问、存多久、如何导出删除、第三方是否处理、争议如何解决；明确不用于无授权广告或训练。
- **验收**：可以执行客户导出、终止、删除和备份到期清理；知道故障或数据事件的联系与处理流程；不能用开源 MIT 许可替代客户数据授权。
- **依赖**：G-01、G-02、B-02；适用地区和具体法律要求确认后，才进入收款与生产资料托管。

### B-04 小规模隔离托管与开通流程

- **拆分任务**：首批客户优先使用明确隔离的应用/数据库/存储配置；标准化开通、账号交付、版本升级、监控、备份、暂停与迁出；记录每实例成本。
- **架构边界**：当前单家族工作区不是现成多租户系统；不能将多个客户数据放入同一业务快照；不同实例的密钥、域名与备份不得混用。
- **交付物**：实例台账、开通与关停清单、恢复记录、访问权限和升级计划；不在源码中写客户凭据或资料。
- **验收**：任一客户导出、升级、恢复或停用不会影响他人；实际完成隔离环境恢复演练；支持时间与响应目标可兑现。
- **依赖**：M0、M4-05 中已提前完成的基础恢复、G-01 的认证实施、B-03；不能因规模化备份自动化未做就跳过基础恢复，也不必先建设所有高级运营功能。隔离方案仍需部署前批准。

### B-05 首批付费试点与客户成功

- **拆分任务**：以 3～5 个家族为小批次；逐个完成小样评估、明确报价、合法收款、授权资料导入、客户核对确认、培训和交付；记录 30/60/90 天使用情况。
- **指标**：区分免费、人情折扣和正常报价客户；记录咨询转付款、实际工时、返工、问题、退款与是否愿推荐。
- **验收**：对明确成果实际付款、验收与全部成本可核实；3 个非强人情客户是样本参考而非通过阈值。贡献非负不足以覆盖研发与固定团队，需观察重复交付收益和成本改善路径；小样本不声称市场匹配。
- **依赖**：B-02、B-03；托管类依赖 B-04；整理类依赖相关 M1 功能。缺少任何交付前提时只做意向验证，不提前收费。

### B-06 收款、订单与订阅自动化（后置）

- **拆分任务**：早期使用合规的手工报价、订单记录和对账；订单量证明必要后再接支付渠道、订单状态、服务权益、退款、到期提醒和对账报表。
- **正确性要求**：支付回调验签与幂等；已退款权益处理；支付成功但开通失败可补偿；套餐变化和续费不丢数据；客户端不能自行宣称已付款。
- **交付物**：现金与订单对账流程、异常订单处理、服务到期和导出流程；第三方费率和上线资质单独核验。
- **验收**：重复/延迟回调、退款、支付与开通顺序异常均无重复收费或错误授权；每天可解释账差；不为少量试单过早造复杂计费平台。
- **依赖**：B-03、B-04、B-05；具体支付渠道、自动续费与否需明确确认。

### B-07 获客与合作渠道实验

- **拆分任务**：制作只含合成或获授权资料的演示；发布导入核对、备份和查谱教程；尝试维护者转介绍、修谱/印刷服务合作；每次只验证少量渠道。
- **边界**：不采集、购买或群发个人信息；不公开客户族谱作为营销样本；合作方接触资料需授权并明确责任。
- **指标**：分别记录触达、有效咨询、试用、付费、渠道现金投入和沟通工时；避免用访问量、星标或注册数代替付费验证。
- **验收**：识别至少一个可重复带来合适客户且成本可承担的渠道；合作业务能按标准交付，而不是接一个客户就形成一套新产品。
- **依赖**：B-02、B-03；扩大渠道投入依赖 B-05 的交付证据，初期不默认投放广告。

### B-08 全成本台账、阶段复盘与停止条件

- **拆分任务**：按真实订单记录获客/未成交售前、小样、清理、核对、客户协调、返工、复核、培训、售后与退出全部工时；资源、税费、收款、退款和第三方成本独立记录；研发与固定投入分开，避免双计。每批次/订单复盘，季度做汇总。
- **交付物**：真实收款、待履约收入、退款、直接成本、工时和可用现金视图；年度预收款不能全当作当期利润。
- **停止条件**：没有购买触发、无人确认疑点、小样不可安全交付、全成本无法解释、返工失控或阶段资金/工时上限到达时，立即停止新增并评审，不等两个季度。资料风险暂停相关路径；负贡献无改善则收窄服务；两季度无付费信号只作长期兜底。
- **验收**：每阶段记录已批准的上限、实际花费、证据、未履约义务与继续/缩小/暂停决定；订单贡献和研发/固定投入分开呈现，不靠忽略劳动宣称盈利。
- **依赖**：成本模板可从 B-02 开始；完整经营复盘依赖 B-05 的真实记录。

## 16. 经营指标、成本与风险控制

### 16.1 产品与经营指标分开看

| 指标 | 统计口径 | 用来决定什么 |
| --- | --- | --- |
| 成果验收/家族激活 | 成果型订单按约定核对、交付与退出验收；在线服务才统计 30 天内导入、核对和受邀查阅 | 客户买到的成果是否成立，不用在线活跃度衡量文件交付 |
| 维护价值 | 90 天内是否发生有意义的补录、核对、审核或版本整理；查阅型客户单列 | 是否存在持续维护需求，不强求日活 |
| 交付效率 | 每项目实际工时、每批记录核对耗时、返工轮次与待核对项 | 是否需要优化流程或提高报价 |
| 关系质量 | 经人工确认的错误关联和遗漏案例；样本来源与审核范围明确 | 能否扩大使用；不以孤立人数减少冒充正确率 |
| 付费转化 | 实际付款客户数与收到明确报价的合格客户数，报告实际样本量 | 报价和价值是否匹配 |
| 续费 | 已到期且具备续费机会的客户中实际续费数；自建/一次性项目单列 | 年度托管是否成立；首年未到期不虚构续费率 |
| 单客贡献 | 净收入扣除全部可归属资源、支付、税费与售前/交付/售后工时；获客分摊规则明确 | 每多一个客户是否改善业务；再独立判断能否覆盖研发和固定团队 |
| 获客投入 | 现金支出和按成本折算的获客工时 | 渠道是否值得扩大 |
| 恢复能力 | 实际恢复成功与否、数据损失范围、恢复耗时、演练日期 | 能否承担托管责任，不只看“有备份” |

客户流失或低频使用不应自动触发催促和营销轰炸。对族谱产品，完成一次重要修谱项目后长期只读也可能是成功使用，应结合客户购买目的判断。

### 16.2 单位经济性示例：不要被低云成本误导

以下仅为成本计算示例，不是对实际 Cloudflare 价格、税费或利润的预测。假设有 30 个家族以每年 399 元购买托管，开发者把自己的支持工时按每小时 100 元计入：

| 项目 | 假设金额或工作量 | 说明 |
| --- | --- | --- |
| 年度托管收入 | 11,970 元 | 假设 30 个客户全部按标准价购买并履约；非销量预测 |
| 基础设施、域名与备份分摊 | 2,000 元/年 | 占位预算，须按实际账单替换 |
| 收款渠道、退款准备及其他直接支出 | 600 元/年 | 占位预算，不是费率承诺 |
| 客服与日常支持 | 60 小时/年，折合 6,000 元 | 每家族每年仅 2 小时；若支持增加，余额会快速降低 |
| 扣除上述成本后的贡献余额 | 3,370 元/年 | 尚未扣开发、获客、税费、管理和其他成本，不是净利润 |
| 若另投入 60 小时获客 | 增加 6,000 元成本 | 同样按每小时 100 元折算后，余额为负 2,630 元 |

这说明低价托管即使产生收入，也未必值得长期投入。更合理的实验是将一次性整理服务按工时单独报价、限制支持范围、提高标准化程度，并验证客户是否接受足够覆盖成本的年费。不能把项目预收款当成已赚取利润，也不能以“云服务很便宜”推断业务盈利。

### 16.3 商业发布前的硬门槛

- [ ] G-01 不仅形成决策，适用的身份验证、账号恢复和停用规则已经实施。
- [ ] 真实客户之间的应用、数据、文件和备份边界经过验证；不是仅前端区分家族。
- [ ] 服务范围、价格、期限、退款、资料处理授权和到期迁出规则明确。
- [ ] 所承诺的导入、核对、导出、备份与恢复功能已在隔离环境验收。
- [ ] 不记录或泄露客户凭据，不将客户资料提交到公共仓库或未经许可的第三方。
- [ ] 支持时间、响应目标、资料损失事件处理与运营负责人明确。
- [ ] 许可、支付、税务及适用地区的数据合规要求完成必要核验。
- [ ] 能在没有后续付费的情况下按已约定流程完成客户退出和资料交接。

### 16.4 投入控制

- 约 23.6 万元六个月团队预算仅是企划中的条件测算，不是本阶段建议或已批准投入；需求验证阶段不预配固定团队。
- 问题→交付→付费→复用→托管各阶段的现金、工时/工程人日上限和截止日均待确认；未批准不自动启动投入，达到上限不自动续期。
- 同时最多验证一个新增收费产品和少量渠道；不同时建设多租户、OCR、支付、离线和印刷业务。
- 开发者兼售后时，默认最多推进 1～2 个需要大量人工核对的交付项目；这是排产建议，不是自动施加给客户的产品限制。
- 在试点成本连续可解释、服务贡献非负之前，不扩大固定成本、不承诺 24 小时客服或赔付级 SLA。
- 若客户主要为一次性整理付费，优先接受服务业务定位；若年度维护付费弱，不用新增低价值功能强推订阅。
- 任何数据完整性或隔离事故优先于新功能和收入目标处理，必要时暂停新增客户。

## 17. 首个 90 天的产品与商业安排

| 时间窗口 | 产品交付 | 商业验证 | 决策点 |
| --- | --- | --- | --- |
| 第 1～2 周 | 必要可行性检查与合成演示，不预设完整研发范围 | 聚焦首发画像、购买触发、成果与不服务范围；确认问题阶段投入上限 | 具体成果购买意愿，而非访谈数量；建议尚待批准 |
| 第 3～4 周 | 根据获准交付方式，定义必做控制和待验收人工流程；线上系统先落实认证与恢复 | 小样、授权、报价、投入上限与退出模板 | 能否安全交付选定成果，不能以人工省略保护措施 |
| 第 5～8 周 | 门槛通过后验证小样、结果一致性与交接；只补已证实瓶颈工具 | 记录售前/核对/返工/复核/培训/售后全成本 | 结果可验收且工时可解释，失败立即转向 |
| 第 9～12 周 | 有证据与资源批准后试单，保留技术替补与责任；托管不默认建设 | 真实报价、付款、验收与单独托管意向验证 | 可重复交付收益；不是单笔非负或工作包完成数 |
| 第 90 天复盘 | 汇总功能验收、关系质量和遗留问题 | 汇总真实收款、工时、成本、拒绝原因和支持负担 | 选择继续作为工具、有限服务业务或继续验证订阅 |

此表为评审建议，不授权实际执行或承诺 90 天完成 M0～M4。用户尚未确认范围、人工替代、预算和报价；缺少阶段批准或安全证据时仅保持讨论、合成演示与意向验证。具体投入与停止矩阵见[企划书第 11 章](projectProposal.md#11-预算单位经济性与投入上限)。
