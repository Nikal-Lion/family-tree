## 1. 执行摘要

### 1.1 项目定位

家族云谱是一套面向家族维护者的数字族谱整理、可信维护与受控查阅工具。长期价值不是让用户每天打开，而是让资料有来源、关系可核对、修改可追溯、数据能恢复、后续维护者能够接手。

建议采用“问题验证 → 交付验证 → 付费验证 → 复用验证 → 独立托管验证”的投入顺序。先证明客户愿为明确成果付费、能够安全交付，再决定是否值得建设持续服务和平台。可信工具仍是能力基础，但不要求先开发完整软件再开始需求验证。

### 1.2 本次评审结论

| 问题 | 结论 |
| --- | --- |
| 原迭代计划是否经过推敲 | 已做代码基线对齐、功能拆分和若干边界分析，但没有完成容量实测、生产配置审计、工时校准或市场验证，不能称为已验证的执行方案 |
| 方向是否合理 | “可靠保存与核对优先、在线 D1 优先、先服务后平台”基本合理；功能池不应被当成必须全部建设的承诺 |
| 排期是否可靠 | 原先 8～12 周属于偏乐观初估，不适合作为单人兼研发、交付与运维的整体承诺；本企划改用人日、有效产能与阶段门禁 |
| 能否长期延续 | 有条件可行；关键是资料迁出、版本兼容、第二维护者、恢复能力、持续运维预算和交接机制，而不是增加更多功能 |
| 能否开始商业化 | 可以先做访谈与匿名演示；处理客户真实资料、试点托管和正式收费各有前置门槛，不能因为“只是试用”就跳过安全措施 |
| 是否已经具备商业安全与运营能力 | 尚不能确认；代码保护不等于生产安全，成功部署也不等于恢复、告警、值守和客户隔离已落实 |

### 1.3 建议立项范围

- **评审建议**：仅有条件开展问题与交付验证，暂不足以支持完整开发、固定团队配置或商业化执行的批准。
- **真实资料处理的必要条件**：身份、权限、授权、数据完整性、备份恢复与责任安排；这些不是可延期的“便利性功能”。
- **待证据支持后再决定**：少量付费整理、持续托管、自动化建设、团队扩充和平台化。
- **总体原则**：客户购买的成果决定最小交付范围；安全与资料完整性决定能否处理真实资料。文档修订不等于批准运营、采购、收费或执行。

### 1.4 本轮修订与待确认项

| PM 建议纳入的变化 | 仍需用户确认 |
| --- | --- |
| 首发聚焦明确负责人、清晰电子资料、近期交付需求的客户 | 实际首发画像、购买触发场景与不服务对象 |
| 按可验收成果定义首发服务，托管独立验证 | 首发成果是电子数据、打印文件还是在线服务 |

| 团队和约 23.6 万元预算降为条件场景 | 实际人员、资金、值守能力和专业支持采购 |

## 2. 依据、假设与尚未验证的事项

### 2.1 已有依据

- 当前仓库具备 Vue 3/TypeScript、Vben/Ant Design Vue 界面、ECharts 图谱、Workers API 与 D1 在线业务存储。
- v0.1.7 已实现全角色手机号加独立密码、首次/重置/升级后强制改密、凭证版本绑定与会话撤销、D1 跨实例认证限流和请求体限制；旧 API Token 旁路默认关闭。手机号是账号标识，不代表已验证手机号持有权。
- 已有独立浏览接口与浏览状态、找家人/看族谱/家族记事入口、首次使用引导、全站大字模式，以及移动端滚动、档案与文件选择优化。

- 当前使用场景以单家族工作区为基础，不能直接把它视为已经隔离的多客户平台。
- 产品基线固定为 `v0.1.7` 的 `fde55b7`，本次核对时本地 HEAD 与该标签一致；工作区另有文档修改，不算作已发布功能。[该提交的 CI 运行 41208839813](https://github.com/Nikal-Lion/family-tree/actions/runs/41208839813) 的 Test、Build、Deploy to Cloudflare 均成功；CI 与标签均不能替代生产配置、真机或恢复验收。

### 2.2 企划假设

| 假设 | 初始用途 | 如何验证或推翻 |
| --- | --- | --- |
| 维护者比普通浏览者更可能承担费用 | 确定首轮访谈对象 | 访谈实际决策人和预算来源；没有付款主体则不进入收费开发 |

| 项目有一名核心工程负责人 | 估计可交付范围 | 明确每周可用时间、交付任务和替补资源 |

### 2.3 未验证清单

市场规模、客户获客成本、正式售价、续费率、供应商实际账单、生产网络体验、平台套餐能力、密钥配置、真实恢复时长和人员可用性均需进一步验证。本企划不以未经核实的竞品价格、行业规模或平台能力作为事实。

旧安全审查限定为审查当时工作区的代码与配置检查；本轮按 v0.1.7 核对相关实现状态，并非新一轮完整安全审查。两者均不能替代生产配置核验、获授权的渗透测试、实际恢复演练或适用法律的专业评估。

## 3. 用户、场景与价值

### 3.1 用户与责任主体

| 角色 | 核心需求 | 对系统的责任 |
| --- | --- | --- |
| 家族资料负责人 | 资料可整理、可核对、可传承 | 确认授权来源与关键关系，接受交付，指定接手人 |
| 数据维护者 | 高效补录、纠错、处理冲突 | 按证据维护，不擅自合并人物或补造亲属关系 |
| 普通成员 | 手机查谱、看档案、提出更正 | 在授予的范围内查阅，不等同于拥有全库导出权 |
| 产品与交付负责人 | 明确范围、客户沟通、可复用交付 | 控制承诺、记录成本、安排验收和售后 |
| 技术与运营负责人 | 稳定、安全、可恢复 | 负责权限、发布、告警、备份、响应和技术交接 |

### 3.2 优先场景

**首发客户画像假设**：有明确资料负责人、较清晰的电子谱文、近期有整理/修谱成果交付需求，而且能够协调同名、承继等关系核对的人群。近期的具体交付期限和购买理由由访谈确认，不用年龄、家族规模或“对家谱感兴趣”替代购买触发。

首发只选择一个主要场景，例如“把现有电子谱文整理为可核对、可迁出的成果包”。客户可能只需要电子文件或打印稿，不需要长期登录系统；受邀查阅和持续补录可以成为后续服务，但不能默认捆绑。

**首期建议暂不服务的需求**：资料授权不明或无人确认关系；要求自动证明历史事实、自动认亲或无证据合并；大量模糊扫描却要求低价自动录入；要求无限返工、永久免费托管或未经授权公开个人资料；要求首单即完成多租户、复杂离线或专属平台定制。这是待确认的接单边界，不是已经实施的客户限制。

现有电子族谱持续维护、专业修谱组织、纸质扫描和弱网走访等场景仍保留为候选，分别验证，不同时面向所有人群建设。

### 3.3 差异化假设

重点不放在“树图更多样”，而放在原文与关系证据、承继语义、人工核对、可靠恢复和服务交接。差异化是否足以形成支付意愿，需要真实客户验证；MIT 源码本身不是排他性壁垒。

## 4. 产品范围与取舍

### 4.1 最小可运营版本

| 模块 | 必须达到的能力 | 不纳入首版的扩展 |
| --- | --- | --- |
| 身份与权限 | 可验证身份、服务端角色控制、账号停用与会话撤销、管理员保护 | 复杂组织层级与任意自定义权限 |
| 族谱维护 | 成员与关系校验、失败不误报成功、冲突不覆盖、删除影响明确 | 无证据自动合并或自动修复 |
| 导入核对 | 原文、候选、决定和提交结果一致；可保留疑点 | 未经过评估的全自动 OCR |
| 查谱 | 手机查找、档案、父系路径或清晰的替代导航 | 全部亲属称谓与多引擎图谱 |
| 备份恢复 | 自动或明确执行的备份、失败告警、隔离恢复、资料可导出 | 无限版本、永久托管承诺 |
| 运营 | 测试环境、发布门禁、基本监控、处理人和替补 | 无资源支持的 24 小时人工在岗 |

最小版本仍需要必要的安全能力，不得通过删减鉴权、备份或恢复来压缩工期。非关键查谱增强可以延期。

### 4.1.1 首期必做、受控人工与延期范围

| 分类 | 候选能力 | 进入首期的规则 |
| --- | --- | --- |
| 不可降级的控制 | 可验证身份、服务端权限、来源授权、客户边界、完整性校验、备份恢复和明确责任 | 采用线上系统时必须实施；离线文件交付也要落实授权、访问保护、校验与恢复，不以“不托管”豁免 |
| 必须满足的成果正确性 | 原文保留、疑点呈现、客户确认、核对结果与交付结果一致、完整迁出 | 可以评估不同流程，但结果和证据不得缺失 |
| 待验证的受控人工流程 | 小样评估、疑点逐条核对、影响范围核对、报价对账、预约备份与客户交接 | 先形成版本化记录、复核、权限与失败处理，再实测工时；未验收前不视为可用替代 |
| 依成果选择的能力 | 查谱界面、父系路径、打印版式、培训 | 只有客户购买成果需要时纳入首期；不能擅自取消已约定交付 |
| 默认延期的便利性/自动化 | 批量核对 UI、复杂审计查询 UI、自动订单/计费、多视图、地图、OCR、多租户、离线 | 等人工瓶颈、真实需求和投资回报有证据后，再选择具体任务 |

例如可以评估人工查看已生成的影响清单，但不能用“人工会小心”替代服务端校验和并发保护；可以手工报价对账，但不能跳过合法收款与退款流程；可以按流程执行备份，但必须验证其实际及时性和恢复能力。需要使用客户数据库时仍遵守既有服务门槛。

每一种人工替代须记录适用范围、执行人、复核人、输入输出版本、实际工时和停止条件。高风险操作无人复核、流程不能重现或支持目标无法满足时，暂停该路径。具体替代方案尚未获确认，本表不授权删减某项功能。

### 4.2 三项优先级修正

- **身份验证仍为真实资料上线的 P0 门槛**。v0.1.7 已提供账号独立密码与会话控制，不重复列为从零开发；后续重点是存量账号升级、临时凭据交付、管理员过渡退出、恢复流程及适用场景验收，额外加强验证仍待决策。
- **备份、告警与恢复的基础部分从 M4 提前到运营基线**。M4 仅保留规模化自动化和高级运营优化。
- **试用和正式付费采用同样的数据安全底线**。试用可以限制人数和功能，不能限制应有的身份验证、隔离、授权和恢复。

### 4.3 与功能清单的关系

[iterationPlan.md](iterationPlan.md) 中的 48 个工作包是需求与实施候选池。本企划决定哪些任务进入当前阶段、需要什么资源以及何时可以进入真实使用。两份文档发生冲突时，应先按本企划中的安全门禁、资源约束和阶段验收修订排期，而不是按旧周数强行执行。

## 5. 技术路线与可延续性

### 5.1 架构原则

- 继续复用当前 Vue/Workers/D1 技术栈，不因商业化设想立即进行微服务或多数据库重构。
- 业务关系语义、导入导出契约与界面展示分离；同一校验规则尽量前后端共用。
- 在线服务端保持权威；客户端预览、缓存和失败回滚不能绕过服务端权限与完整性校验。
- 全量快照保存先测量再优化；改成增量接口时同时处理修订、审计和旧客户端，不能只优化单条请求。
- 首批多个家族优先考虑批准后的隔离实例，且仍需共享运行手册与版本管理；独立实例不等于没有共用账号或密钥的风险。

### 5.2 数据延续性

1. 保留原文、来源和不确定性；标准日期或名字规范化不能覆盖原始记载。
2. 持久化 schema 变化需要版本、迁移样例、备份往返和回退兼容性说明。
3. 业务快照、账号配置、审计、附件和基础设施分别定义备份与迁出范围。
4. 数据替换时处理账号绑定、收藏和待审核提议，不能因复用数字 ID 指向另一个人。
5. 客户终止服务时可按协议获得可读资料和完整业务数据，不强制续费才能取回原始资料。
6. 长期维护计划必须包含停服、运营者离开、账号失联和托管供应商变更时的交接路径。

### 5.3 工程延续性

| 机制 | 具体要求 |
| --- | --- |
| 代码与设计 | 关键关系语义、迁移、发布和恢复有文档；避免只有一个人理解 |
| 自动化 | 业务不变量、权限、导入、备份与并发回归纳入维护范围 |
| 依赖维护 | 每月检查依赖和安全通告，按风险处理；按季度检查运行时支持状态与供应商变化 |
| 本地 vendor | 保留 Vben 来源与本地修改记录，升级时核对差异与许可，不无限期冻结 |
| 人员替补 | 至少第二名有授权、受培训的技术人员能够恢复环境、定位告警和执行回退 |
| 配置恢复 | 版本化非敏感配置；密钥经受控渠道保管、轮换与应急恢复，不写入仓库 |

### 5.4 资金延续性

年度托管是持续义务，不是一次性交付后的无成本收入。应为每个服务周期计提资源、支持与退出成本，避免用全部预收款开发新功能。没有可兑现的预算、人员和退出方案时，不销售“长期可靠托管”。

## 6. 安全策略与上线门槛

### 6.1 保护对象与威胁范围

保护对象包括成员个人资料、关系、照片、葬地坐标、登录身份、备份、审计和后续收款记录。主要威胁包括冒用身份、角色越权、误删与恶意覆盖、客户间数据混用、备份泄露、管理员账号失控、供应链风险和不可恢复的变更。

安全工作应同时处理保密性、完整性和可用性；“文件有备份”不能抵消身份验证缺失，“管理员可以登录”也不等于所有 API 受到保护。

### 6.2 必须实施的控制

| 领域 | 最低要求 | 验收证据 |
| --- | --- | --- |
| 身份验证 | 普通用户和维护者均证明对凭据或受信身份的控制；管理员使用独立账号并加强验证 | 冒用已知手机号不能取得会话；错误和失效身份被拒绝 |
| 授权 | API 服务端按角色和客户边界检查；敏感数据读取与导出均受约束 | 角色矩阵、直调接口与越权回归 |
| 会话 | 有期限、可撤销；账号停用与身份变化及时生效；高权限操作必要时重新验证 | 停用、退出、换角色和恢复后的会话用例 |
| 输入与数据 | 严格 schema、引用/循环校验、大小与资源预算、事务和修订控制 | 恶意或错误输入不留下部分写入 |
| 导入与导出 | 不执行输入中的脚本；CSV 防公式；导出不包含未授权字段或凭据 | 文件格式与字段权限回归 |
| 密钥与运维 | 最小权限、不同环境隔离、轮换与应急撤销、受控访问 | 配置核验和撤销演练，不在日志中打印密钥 |
| 备份与附件 | 受控访问、传输与存储保护、独立恢复途径、删除与保留期规则 | 未授权访问被拒绝，恢复与迁出演练成功 |
| 可追溯性 | 关键写入审计、异常告警、诊断脱敏 | 可以还原操作过程，但不会保存无限量敏感正文 |

具体认证方式、缓存策略、日志保留期和密钥管理方式需经决策后实施。加验证码或限流不能替代身份验证；使用云平台也不能替代应用权限控制。

### 6.3 v0.1.7 安全基线、历史发现与证据边界

本企划区分“标签中已实现的控制”“旧版本发现”“生产配置待核验项”和“未来设计要求”。认证改动已纳入 v0.1.7，不再描述为并行会话的未提交方案；本次版本对齐不构成完整安全复验。

基线保留服务端角色检查、随机会话令牌及摘要保存、到期/撤销/启用状态检查、参数绑定、共享数据校验、事务与修订号防覆盖，并新增所有角色的独立密码。新建、重置及旧凭据升级后必须改密；15 分钟受限会话不能读取族谱或管理账号。凭证版本绑定会话，改密、重置和身份变更撤销旧会话，升级前无凭证版本的会话失效。认证入口使用 D1 跨实例限流，并限制请求体为 4096 字节。

以下保留旧审查发现及原严重性，仅说明其在最新基线中的处理状态；旧行号和置信度不作为 v0.1.7 的当前漏洞定位。

| 旧版本发现 | 原严重性 | v0.1.7 实现状态 | 上线仍需核验 |
| --- | --- | --- | --- |
| 普通用户/维护者仅凭手机号取得会话 | HIGH | 所有角色均验证密码；无独立密码的普通账号不能登录，旧免密会话失效 | 前端与 Worker 同版本、存量账号配密与改密完成，无旧免密入口继续运行 |
| 管理员长期共用环境级口令，单账号撤权不足 | MEDIUM | 已设独立密码的管理员不再接受共享口令；共享 Secret 仅用于初始化或尚未配密的旧管理员过渡，过渡会话无业务访问权 | 所有管理员完成独立改密，受控退出过渡 Secret；人员退出、管理员恢复和会话撤销流程经过验收 |

**后续要求**：复用独立密码方案，不重复安排“从零补身份验证”。先验证升级、凭据私密交付、线下身份确认与管理员恢复，按客户场景决定额外加强验证。`ALLOW_LEGACY_API_TOKEN_AUTH` 默认关闭，生产须核对未启用；不能开启该旁路代替账号恢复，也不能常规回退到旧免密版本。密码证明凭据控制，不等于短信验证、现实身份认领或资料授权。

**数据可见范围仍需产品决策**：普通用户通过 `/api/browse-data` 获得获准的完整族谱资料，维护快照 `/api/family-data` 仅供维护人员/管理员使用。接口与角色隔离已经实现，但不构成敏感字段过滤；“只读”不等于“仅看到脱敏字段”。如果试点需限制在世成员资料、照片或坐标，必须落实服务端返回范围并回归，不能只隐藏按钮。

客户端 token 仍保存在 localStorage，独立密码和限流也不能替代浏览器侧防护、平台防护、资料授权或客户隔离。生产上线还需独立核验实际部署版本与环境绑定、账号迁移、旧 token 旁路、管理员过渡退出、管理平台权限、生产/测试隔离、日志脱敏与保留期、备份新鲜度、告警送达和恢复演练。

本次未执行漏洞利用，未读取真实族谱或生产密钥，也未核验生产访问控制。因此可以确认上述控制存在于版本基线，不能据此声称生产已全面安全、旧风险在所有部署中已关闭，或不存在其他风险。

正式开放真实资料前必须关闭已确认的阻断问题，并对最终待发布版本复验。修复未经验证、仅写在规划中或存在于未部署代码里，都不能计为生产风险已经关闭。

## 7. 正常运行与故障恢复方案

### 7.1 可用性承诺分层

系统不可能获得“永不故障”的保证。可交付的是明确目标、可检测的故障、可执行的恢复步骤及负责的人。

| 指标 | 试点建议 | 条件与限制 |
| --- | --- | --- |
| 在线可用性 | 先建立连续 30 天实际基线；具备响应能力后，以月度 99.5% 作为内部候选目标 | 不是对外 SLA；工作时段支持本身不足以保证全天可用性 |
| 支持窗口 | 初期建议工作日 09:00～18:00，写明时区和节假日安排 | 网站不按窗口主动停服；窗口外响应不作未获资源支持的保证 |
| 故障发现 | 关键探测建议 1～5 分钟一次，失败触发主责与替补通知 | 要验证告警确实能送达，而非只创建监控面板 |
| 普通故障响应 | 支持窗口内建议 30 分钟内确认；常见应用故障目标 2 小时内恢复 | 为待演练的内部目标；窗口外与灾难故障另行约定 |
| 恢复点目标 RPO | 低频试点可讨论不超过 24 小时的数据损失窗口 | 客户必须接受；每日备份失败即可能违约，需要新鲜度告警 |
| 恢复时间目标 RTO | 在实际值守覆盖的场景中验证，例如常见故障 2 小时 | 必须计入发现、等待响应和恢复验证；不能只算执行恢复命令的时间 |

以上数值是资源规划的候选值，不是已达标事实。正式承诺前应确定真实使用时间、数据损失容忍度、供应商恢复能力与人员排班。若要求全天 2 小时恢复或接近零数据损失，必须先增加相应备份频率、值守和预算，不能沿用低成本试点方案。

### 7.2 必须监控的项目

- 页面与关键静态资源能否访问；不能仅靠首页返回 200 判定业务正常。
- API 的读成功率、写成功率、服务端错误率、延迟和数据库连接异常；将权限拒绝、校验错误和版本冲突与系统故障分别统计。
- 备份是否成功、最近有效备份时间、校验状态和恢复演练日期。
- 部署结果、应用版本与数据库版本是否匹配，异常是否从某个版本开始。
- 请求量、存储、轨迹点数和资源使用趋势；设定费用预警和异常增长处理。
- 身份验证异常、权限拒绝突增及关键管理员操作；日志内容必须脱敏。

真实生产探测优先只读且最小权限。需要写入验证时使用专门的合成资料环境，不定时修改真实族谱。监控中断与告警通道失效本身也需要检查。

### 7.3 发布流程

1. 本地或 CI 完成与变更对应的逻辑、权限、迁移和浏览器验证。
2. 在独立测试环境演练升级，不能让预览命令误连生产数据库。
3. 明确待发布版本、数据库兼容性、备份、回退步骤和发布责任人。
4. 高风险数据迁移需要第二人复核；无合适替补时延期，不在无人可处理时发布。
5. 发布后检查关键只读链路、版本、错误率与资源异常；保留观察窗口。
6. 异常时停止扩大影响，按兼容性决定应用回退、关闭写入或进入恢复；不盲目将旧程序部署到不兼容的新数据库。

CI 成功和云端部署成功属于必要证据，不是完整线上验收。v0.1.7 的 CI 结果仅对应 `fde55b7`；对后续工作区改动、未经检查的生产配置和未来架构，不能沿用该结论。

### 7.4 备份与恢复

| 层次 | 内容 | 注意事项 |
| --- | --- | --- |
| 业务快照 | 全部约定的业务集合、原文、关系、计数器和顺序 | 现有 JSON/SQLite 范围以实际契约为准 |
| 认证与运营状态 | 账号、权限、必要配置和审计 | 独立访问控制；恢复后处理旧会话，不默认让历史令牌继续有效 |
| 附件 | 后续受管理的图片、谱页与引用清单 | 外部 URL 不代表本系统已经备份其内容 |
| 基础设施 | 非敏感部署配置、域名与服务清单、密钥恢复与轮换程序 | 密钥不放入普通业务导出；应急访问有授权与记录 |

初期建议每日备份并在批量导入、整库恢复、重要迁移前保留恢复点。短期保留可先讨论 7 个日版本与 4 个周版本，最终以授权、成本及恢复要求为准，不无限期保存敏感资料。

备份应具有独立的访问控制与合理的故障隔离，避免生产账号失控时同时失去全部备份。至少在首次真实上线前、重大迁移后及按约定周期进行隔离恢复演练；初期可采用每月一次。演练必须核对人物、关系、原文、轨迹顺序和计数器，而非只确认文件能打开。

### 7.5 事故处理与复盘

| 等级 | 示例 | 首要动作 |
| --- | --- | --- |
| 严重 | 资料泄露、跨客户访问、不可恢复丢失、关键身份控制失效 | 停止相关写入或访问、控制影响、保留必要证据、通知负责人，按适用规则处理客户沟通 |
| 高 | 全站不可用、持续保存失败、关键恢复链路失效 | 主责与替补响应，回退或恢复，保持明确状态通告 |
| 一般 | 非关键页面异常、局部兼容问题 | 保留替代操作、排入修复，避免干扰数据核心流程 |

恢复后记录时间线、影响范围、根因、恢复证据和预防任务。涉及数据恢复时，应得到有权决定的负责人确认；修复过程中不能覆盖唯一故障现场或将敏感数据上传到未授权平台。

## 8. 人员与人力配置

### 8.1 不同阶段的建议

| 阶段 | 建议配置 | 能承担的范围 |
| --- | --- | --- |
| 自用/需求验证 | 1 名核心开发者，配合实际资料负责人验收 | 持续改善工具；不对外承诺全天商业服务 |
| 3～5 家族付费试点 | 约 1.5～2.0 个全职当量，通常由 2～3 名实际人员分担；必须有技术替补 | 有限范围交付、工作时段支持与隔离托管 |
| 稳定的小型产品 | 按需求逐步配置 2 名工程人员、1 名产品/交付人员，加兼职测试/运维与专业服务 | 可重复发布、客户支持和交接；是否需要增加人手取决于实际工时 |
| 全天候服务或机构扩展 | 单独设计轮值、备份、休假覆盖与升级响应 | 不可将前一阶段兼职替补直接当作 24 小时在岗能力 |

全职当量表示投入量，不是要求每种职责都招聘一名全职人员，也不代表工作可以自动并行。AI 可以协助编码、文档和用例，但不能作为值班人、资料授权人、独立责任人或无需复核的谱文裁定者。

本表仅为不同业务情景的配置参考，不建议在需求验证阶段预先招聘固定团队。每阶段按实际工作量安排主责、技术复核/替补与必要专业支持；进入托管责任后仍必须具备真实响应能力，不能以“精益验证”为由省去关键责任。

### 8.2 首批试点的职责配置

| 职责 | 建议投入 | 主要责任 |
| --- | --- | --- |
| 核心全栈工程 | 1.0 全职当量 | 前后端、迁移、自动回归、发布与技术问题处理 |
| 产品/交付/资料协调 | 0.5 全职当量 | 访谈、范围、报价、资料授权协调、人工核对组织、验收和客户支持 |
| 第二工程人员 | 0.2 全职当量起 | 关键变更复核、独立验收、恢复演练、技术替补 |
| 安全/隐私/财税专业支持 | 按里程碑或必要时采购 | 上线前评审、适用规则与合同、收款及税务处理 |
| 客户资料负责人 | 每个项目指定，按项目投入 | 对来源、同名消歧、承继关系和最终成果作有权确认 |

上述 1.7 全职当量已经包含常规测试和运维职责；不能同时把它们视为免费额外产能。大量人工录入与复杂校对需单独估工，不能默认包含在 0.5 的交付投入里。

### 8.3 责任与替补

| 工作 | 执行主责 | 必须参与的复核或授权 |
| --- | --- | --- |
| 产品范围与对外承诺 | 项目/交付负责人 | 技术负责人确认能实现、能支持 |
| 高风险发布与数据库迁移 | 技术负责人 | 第二工程人员复核；数据影响由有权负责人确认 |
| 关键家族关系确认 | 客户资料负责人 | 维护者依据原文核对，不由 AI 自动最终决定 |
| 备份、告警、恢复 | 技术负责人 | 替补掌握流程并实际演练；恢复范围经授权 |
| 服务报价与退款 | 项目负责人 | 根据成本和已约定条款处理 |
| 安全事件 | 预先指定的事件负责人 | 技术、交付及必要专业支持共同处理 |

至少两名实际人员应能在授权下接手关键技术操作。兼职替补的可联系时间、响应义务和报酬需明确，不能只把名字写在文档里。高风险操作确实无人复核时，应选择延期或停用相关功能，而非默认为无风险。

| 小计 | 46～70 | 包含开发侧验证；不包含大量客户人工录入、法律服务与市场访谈 |
| 加入约 25% 未知与返工余量后 | 约 58～88 | 用于资源占用预估，后续应以实测替换 |

一名全职工程人员兼顾支持、协调和维护时，若每月只有约 12～14 个有效功能开发人日，完整上述范围更接近 **4～8 个月**，而不是默认 8～12 周完成。增加人员也不会线性缩短依赖链，须考虑复核和协同成本。

首个 90 天应聚焦“安全稳定基线 + 一个范围受控的交付流程”，而不是承诺完成全部 M0～M3。只有对应门槛通过后才能让真实客户进入试用或收费。

### 9.2 工作节奏

- 按两周进行计划和复盘，每个周期只安排有明确验收条件的少量任务。
- 核心工程人员预留日常维护与支持时间，不按 100% 新功能开发估算。
- 同时推进的高人工交付项目初期建议不超过 1～2 个，按实际核对工时调整。
- 安全、数据完整性与线上事故优先于新功能；未达发布门禁时不因商业日期强推。
- 每次复盘更新实际人日、等待时间、返工原因和未决事项，避免长期沿用初始乐观估计。

## 10. 商业模式与验证

### 10.1 首发服务建议

首发只选一个范围清晰的成果型服务：获授权电子谱文的小样评估、整理、核对清单、客户确认和退出交付。是否交付在线系统、可读文件或打印成果，应由客户购买目的与实际能力确定，不先承诺完整软件。

一次性整理与持续托管是两种独立假设。整理成交不证明客户愿付年费；只有另行验证托管需求，并满足身份、隔离、恢复与支持条件，才提供年度服务。普通族人受邀查阅不建议首期逐人收费，专业排版和专用部署按额外工作量单独订约。

### 10.1.1 可验收成果定义

| 环节 | 必须约定并记录的内容 |
| --- | --- |
| 输入 | 授权范围、源文件版本、抽样质量、处理范围；哪些资料不能可靠解析 |
| 小样与范围 | 选取覆盖普通记录、同名、承继和缺失等实际复杂度的小样；确认正式工作量、费用与不包含的任务 |
| 处理结果 | 可读整理成果与原始依据的对应关系；结构化数据只覆盖已确认或明确标记的不确定内容 |
| 疑点清单 | 未匹配、冲突、缺字、关系不明和待客户确认项；保留疑点是允许的成果，不以减少问题数宣称正确 |
| 客户确认 | 谁有权确认、确认的版本、处理意见、哪些未决项继续保留；不默认让客户承担全部处理错误责任 |
| 验收 | 核对后的成果与交付一致；可读文件、数据包或打印稿按选定方式检查；订约前定义修正、返工和拒收处理 |
| 退出交付 | 原始资料、整理成果、必要的完整业务备份及说明通过受控渠道移交；确认删除/保留期限；不要求继续托管才能获得成果 |

线上功能完成数、导入记录数和试用人数不能代替这份验收。某一成果格式不可提供时，先改变服务提案并取得同意，不能交付后再解释缺失。

### 10.2 定价与范围

配套迭代文档中的托管 299～699 元/家族/年、整理 999～2,999 元/项目起等仅保留为访谈假设，不是确认售价。实际报价应依据样本质量、记录量、校对轮次、资源额度、支持期限和税费处理。

以每小时 100 元的占位劳动成本计算，999 元仅对应 9.99 小时劳动，2,999 元仅对应 29.99 小时劳动，尚未扣除资源、税费、收款与其他成本。399 元年费中的 2 小时支持已消耗 200 元劳动成本。记录量、页数与反馈轮次不能单独限制成本；关系复杂度、源文质量、客户协调和修改范围也必须小样评估。

### 10.2.1 真实订单全成本台账

| 分类 | 记录内容 |
| --- | --- |
| 售前 | 获客、沟通、小样、报价、未成交客户的工时与费用，和订单间分摊规则 |
| 交付 | 清理、解析、人工核对、客户协调、返工、导出/排版、独立复核、培训 |
| 售后 | 验收后的修正、技术支持、恢复、退款处理和退出迁出 |
| 非人工成本 | 资源、存储、备份、工具、第三方服务、收款、实际税费与外包 |
| 收入与义务 | 实际收款、退款/折让、待履约部分；记录工时单价与工时估算和实测差异 |
| 贡献与固定投入 | 订单净收入减可归属全部变动成本得到订单贡献；研发、固定团队及未分摊费用另列，避免重复计入或遗漏 |

贡献非负只说明此单没有增加可归属亏损，不证明足以覆盖研发和固定团队。报价应给出预计全成本、必要余量和超范围处理；实际超出时查原因、调整未来范围与报价，不擅自向已订约客户追加费用。

不得默认承诺无限空间、无限客服、永久托管或“所有家族关系都正确”。对历史事实的判断应由有权资料负责人确认，服务方负责按约定流程处理和呈现证据。

### 10.3 获客与客户验证

| 阶段 | 行动 | 通过信号 |
| --- | --- | --- |
| 问题验证 | 访谈 8～12 位潜在负责人，了解替代方案、工时、预算与决定权 | 找到明确问题和愿意试用的实际负责人 |
| 交付验证 | 合成演示后，满足资料门槛再开展小批量授权小样与成果交付 | 选定成果安全、正确、可验收、可退出；线上查阅仅在客户需要时验证 |
| 付费验证 | 在服务就绪后提供明确报价并完成真实交易 | 非强人情客户为明确成果付款并验收；约 3 个案例可作观察样本，不是机械通过阈值 |
| 复用验证 | 比较不同客户的售前、交付、返工和支持全成本 | 重复交付有可解释的收益；贡献能够形成覆盖固定投入的路径 |
| 托管验证 | 单独验证维护频率、年度预算、托管价值；满足服务门槛后才试约，并等待真实到期续费 | 整理购买不能替代托管付款，首年兴趣不能替代到期续费 |

这些数量是实验规模，不是销量预测或市场成熟证明。未验证交付前不扩大获客投入；不采买个人信息、不公开客户族谱营销、不将资料用于未经授权的训练。

## 11. 预算、单位经济性与投入上限

### 11.1 预算使用原则

预算必须区分实际现金支出与劳动经济成本。创始人不领取工资可以降低现金消耗，但不能据此认定业务盈利。约 23.6 万元六个月预算只保留为条件场景测算，不是当前推荐投入、已批准预算或启动门槛。优先按问题、交付、付费、复用、托管逐段决定投入，不预先为整条路线配置固定团队。

每阶段开始前必须确认现金上限、各角色工时/工程人日上限、截止日、执行与复核资源及上一阶段的未履约义务。**当前未给出预算数字，因此全部上限为“待确认”，不视为无限额度；确认前不启动新增采购、招聘、客户收费或商业交付。** 以下场景测算仍不代表招聘市场行情或供应商报价。

### 11.2 小规模试点团队测算示例

| 项目 | 测算假设 | 月度金额 |
| --- | --- | --- |
| 核心工程人员 | 1.0 全职当量，按每月总成本 18,000 元占位 | 18,000 元 |
| 产品与交付 | 0.5 全职当量，按全职每月总成本 12,000 元占位 | 6,000 元 |
| 备份工程人员 | 0.2 全职当量，按全职每月总成本 20,000 元占位 | 4,000 元 |
| 基础设施与工具 | 测试/生产、备份、域名、监控等占位 | 800 元 |
| 日常专业支持储备 | 非一次性上线评审的后续支持占位 | 1,500 元 |
| 月度合计 | 不含额外大量录入和超范围定制 | 30,300 元 |

若按此配置预留六个月，日常预算为 181,800 元；另以 15,000 元作为一次性上线评审和合同等准备的占位预算，再预留约 20% 不确定性，总量约 **23.6 万元**。这不是建议立即投入的金额；应先用实际人员安排与报价替换每一项，并按阶段释放预算。

如果以个人工具方式推进，可显著降低外部现金支出，但应同步降低交付速度和服务承诺，而不是仍然承诺同等商业能力。

### 11.3 收入是否能支撑团队

按 30 个家族、每年 399 元计，年收入仅 11,970 元，不能支持上述团队。即便有 600 个家族、每年 599 元，年流水也只有 359,400 元，仍低于样例固定年成本 363,600 元，且还未计入规模增长后的额外获客与交付成本。

因此初期 3～5 个客户的作用是验证问题和交付，不是养活一支专职团队。要成立为可持续业务，需要提高服务价值与交付效率、形成合理的项目收入、验证托管价格和续费，或接受它长期保持小规模工具/服务业务的定位。

### 11.4 财务与停止条件

- 每个项目记录收款、待履约义务、退款、人工、资源、获客和支持成本。
- 首批订单完成后，依据实际工时调整范围和报价；持续负贡献且无法纠正时不扩大客户规模。
- 每次访谈批次、小样交付和订单结束就执行继续/转向/停止评审；未找到购买触发、小样无法安全完成或全部成本无法解释时，不等待两个季度才调整。
- 阶段资金或工时上限到达即停止新增投入并评审；除非得到明确批准，不自动延长和加预算。保留已订约义务的履约与退出安排。
- 两个季度无有效付费信号仍是更长期的兜底停止条件，不替代更早的阶段判断。
- 保留现有客户履约与退出预算，不把预收年费全部用于开发新功能。
- 任何会影响数据安全或恢复能力的降本方案不得悄悄实施，必须重新评估并告知受影响客户。

### 11.5 分阶段投入与停止矩阵（待批准模板）

| 验证阶段 | 投入上限与范围 | 必须取得的证据 | 停止或转向触发 |
| --- | --- | --- | --- |
| 问题验证 | 现金、访谈/协调工时、截止日待确认；原则上只做访谈、合成演示和必要可行性评估，不建设完整产品 | 同一首发画像存在具体近期交付需求、现有替代成本、实际决策人；明确客户要什么成果 | 只有兴趣而无负责人或近期触发；在约定批次中找不到可付费场景；达到资源上限 |
| 交付验证 | 单个小样或小批次现金、工程/核对/复核工时待确认；不开放无限免费试用 | 已获授权且门槛满足，成果可验收、可迁出；全流程工时、疑点和返工可解释 | 安全/正确性无法保证；关系无人确认；小样复杂度或返工超出可报价范围 |
| 付费验证 | 试单数量、售前及履约预算、工时和退款准备待确认；不得无准备先收费 | 对明确成果真实付款、按范围验收；全成本和客户购买理由可核实 | 只接受人情折扣；无人接受可覆盖合理成本的提案；付款但持续无法履约 |
| 复用验证 | 新批次数量、优化工程人日和交付预算待确认；只优化已证实瓶颈 | 重复项目多数流程可复用，返工可控；贡献与覆盖固定投入的路径明确 | 每单都需重写产品；长期依赖高人工和亏损报价；增量投入没有成本改善 |
| 托管验证 | 托管期限、运营现金、支持/替补工时和恢复目标待确认；按客户真实需求另行立项 | 客户另付托管费，安全和运营可兑现；持续维护有价值，到期续费按实际队列记录 | 客户仅需一次性文件；托管定价不足以承担责任；告警、恢复或值守无法兑现 |

8～12 次访谈、3～5 个试点和 3 个付款案例仍可作实验规模参考，但不能机械地作为通过阈值。具体投入上限、允许重试次数和通过判据必须确认后执行，失败时记录原因并优先收窄场景，不自动扩建。

## 12. 18～24 个月阶段路线

| 阶段 | 产品与工程目标 | 经营与组织目标 | 阶段门禁 |
| --- | --- | --- | --- |
| 0～3 个月 | 核实基线、完成优先安全与运营任务、跑通一个最小资料流程 | 访谈、授权与报价模板、明确负责人和替补 | 不以完成日期替代身份、恢复和资料授权门槛 |
| 3～6 个月 | 完善核对与必要查谱；按实测完善隔离托管 | 少量真实付费交付，记录全部工时与支持 | 客户验收、单笔贡献、恢复与权限均有证据 |
| 6～12 个月 | 按客户需求选择资料库、修谱版本和交接能力 | 标准化范围、有限渠道实验、持续维护预算 | 不同客户可复用，非高度定制人力外包 |
| 12～18 个月 | 有证据才建设多家族平台或专业排版 | 验证到期续费与运营人力 | 续费、客户隔离、费用和替补能力支持扩展 |
| 18～24 个月 | 从 OCR、离线采集、格式互通中最多先选一个重点 | 选择扩张、维持小型业务或回归工具定位 | 新方向有真实需求、可承担风险和资源 |

月份只作观察窗口，不是阶段自动升级日。只有第 11.5 节证据与资源批准支持时才延长或进入下一阶段；后期功能不属于首期投资自动附带的承诺。

## 13. 首个 90 天行动安排

| 时间窗口 | 核心行动 | 交付证据 |
| --- | --- | --- |
| 第 1～2 周 | 确认一个首发画像、购买触发、成果、不服务范围及问题验证投入上限；只做合成演示和必要可行性检查 | 需求证据、未决清单、实际负责人和预算/工时上限；不是访谈数量达标 |
| 第 3～4 周 | 有问题证据且获准后，定义小样交付方式、必做控制与待验证人工流程；采用线上系统则先完善相应认证、隔离与恢复 | 范围确认、安全控制、版本与复核记录、授权条件 |
| 第 5～8 周 | 门槛通过后验证选定成果的小样与交接，按瓶颈补必要工具，不默认开发全部 M1/M2 | 可验收成果、疑点清单、客户确认和售前/交付/售后全成本 |
| 第 9～12 周 | 证据与资源支持才开展明确范围的付费试单；托管需求独立验证，不随整理服务默认建设 | 实际付款、验收、贡献与失败原因；不靠工作包完成数通过 |
| 第 90 天 | 复盘安全、可用性、人力、客户反馈和现金消耗 | 明确继续、缩小或暂停，不仅汇报新增功能数 |

若安全方案、恢复能力或合法资料处理条件未满足，第 9～12 周仍然只做合成演示和意向验证，不为赶销售节点放宽要求。

该表为评审后的观察节奏，不授权实际执行。没有用户确认的阶段资源与服务范围时，保持讨论与文档状态。

## 14. 风险登记与处置

| 风险 | 早期信号 | 处置原则 | 责任主体 |
| --- | --- | --- | --- |
| 身份冒用或越权 | 仅凭可获知的信息取得身份，权限回归失败 | 阻断真实资料开放，修复并复验 | 技术主责 |
| 资料误关联或覆盖 | 核对结果与保存不一致、冲突后强制覆盖 | 停止高风险写入，保留原文与恢复点 | 技术 + 资料负责人 |
| 备份不可用 | 文件存在但未成功恢复、备份过期 | 视为运营缺陷，不继续扩大承诺 | 运维主责与替补 |
| 单人依赖 | 只有一人掌握部署、密钥和恢复 | 建立授权替补与实际演练 | 项目负责人 |
| 低价高人工 | 核对、客服或返工超出报价预算 | 限范围、重新报价或停止该服务 | 交付负责人 |
| 多客户混用 | 人工复制配置、共用快照或访问凭据 | 独立核验边界，必要时暂停新增 | 技术主责 |
| 云平台或费用变化 | 配额逼近、延迟增加、资源账单上升 | 监测、限额、备份迁出和成本复盘 | 技术 + 项目负责人 |
| 合规与资料授权 | 上传者无权委托、隐私或删除请求无法执行 | 暂停相关处理，寻求必要专业意见 | 项目 + 专业支持 |
| 需求膨胀 | 同时启动地图、OCR、多租户、离线与计费 | 保留单一核心目标，重新排序 | 产品负责人 |
| 无付费需求 | 兴趣高但无人接受明确报价 | 停止扩大商业投入，调整场景 | 项目负责人 |

不为每个风险编造概率。优先记录已知证据、影响和关闭条件；实际发生后更新范围与优先级。

## 15. 阶段验收与决策清单

### 15.1 立项前

- [ ] 确认目标首先是家族自用、整理服务还是托管业务，三者不能混用服务承诺。
- [ ] 确认首发画像、购买触发、不服务对象、具体可验收成果及疑点确认责任。
- [ ] 明确实际可投入人员、有效人日、预算上限与至少一个技术替补。
- [ ] 选定一个首发场景，不把 48 个工作包都列为首期必做。
- [ ] 确认首期必做/待验证人工/延期范围，人工替代有记录、复核及停止条件。
- [ ] 确认本阶段现金和人力上限、截止日、通过证据与提前停止条件，不先承诺六个月固定团队。
- [ ] 确认安全决策、运营地区、资料授权与支持窗口的负责人。

### 15.2 真实资料上线前

- [ ] 当前最终版本的阻断安全问题关闭，身份与权限经过复验。
- [ ] 备份、恢复、告警与高风险操作路径经过验证。
- [ ] 清楚区分本地、测试和生产，确认线上实际版本。
- [ ] 来源授权、字段可见性、导出与删除规则落实。
- [ ] 主责、替补与故障处理路径实际可用。

### 15.3 收费前

- [ ] 服务范围、期限、价格、退款、到期导出与资料交接明确。
- [ ] 客户隔离、支持能力和恢复目标与合同一致。
- [ ] 业务与账号/基础设施灾备边界已向有权负责人说明。
- [ ] 支付、开票/税务及适用的数据处理要求完成必要核验。
- [ ] 实际交付工时和资源成本能够支持报价。

### 15.4 扩张前

- [ ] 非人情客户的付款和验收证明服务有价值。
- [ ] 单客贡献、支持负担、恢复与安全能力支持更多客户。
- [ ] 增加客户不会依赖未经培训的人临时处理关键资料或运维。
- [ ] 平台化或新功能有具体触发条件，而非因为路线图写了月份。
