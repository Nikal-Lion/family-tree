- 管理端采用侧栏布局；族谱总览采用轻量顶部布局。`user` 仅可访问总览；`maintainer` 可访问总览与数据维护；`sysadmin` 还可访问系统管理。`v0.1.4` 保留成员手机号直接登录，为维护人员增加独立密码；系统管理员继续使用服务端固定验证密码，详见下文版本说明。
- `/app` 在恢复登录会话后按角色跳转；退出登录会清空会话并重新载入页面，避免跨账号复用内存中的工作区。

- 第一阶段已提交（`66725d1`），第二阶段已提交（`6693ccc`），第三阶段已提交（`19ccc2b`）。第四阶段只读总览与图谱浏览已随 `v0.1.3` 发布；`v0.1.4` 包含后续登录、浏览与维护隔离及首次使用引导。
- 维护页 `ManagePage` 分为“族人管理”“事件与轨迹”“资料与备份”三个 Tab，全部使用独立的 Ant Design Vue 管理组件，不再桥接旧 `FamilyWorkspace`。切换 Tab 保留已打开页面的筛选与待核对预览。族人管理支持姓名/ID/分支/别名搜索、分页、全字段表单与谱载代数；档案 Drawer 展示配偶、子女声明、别名、关系、纪年、葬地，并支持新增/删除配偶。
- 第三阶段提供事件表格与编辑弹窗、GPX 上传与轨迹元数据管理、备份校验与九集合恢复预览、Markdown 统计/问题清单/分代预览/原文样本；系统管理改为独立 `SystemPage`，账号搜索分页、三角色与启停操作、D1 诊断统一使用 Ant Design Vue。所有写操作继续等待服务端确认，失败保留输入或预览。按当前范围决定，OCR 暂缓：不挂载已有实验组件、不提供识别或 OCR 导入操作，保留代码但不宣称实现完成。
- 前后端共用 `src/services/importExport.ts` 的严格 schema 4 契约，保留九个业务集合、全部 `next*` 计数器和 `generationNumber`，兼容 schema 2/3 并将历史 `spouseIds` 迁为显式配偶关系；坏引用、循环与重复 ID 会拒绝，不静默丢弃。
- 真实 Workers 入口 `api/index.ts` 在 D1 同一 batch 事务中保存全字段，并以 `If-Match` 修订号比较并交换（CAS）拒绝并发覆盖。store 写入串行排队，等待云端确认才反馈成功，失败完整回滚。
- JSON 与真正的 SQLite 二进制备份均保存完整业务快照，不含登录账号和会话。SQLite 使用版本 1 的 `family_backup(format_version,payload)` 单行 JSON 快照格式，不是任意 SQLite 数据库导入，也不是 D1 整库镜像。
- 当前以在线 D1 为主：空库保持为空，不自动 seed，不在失败时静默回退 localStorage，不自动上传或删除历史 localStorage。离线编辑同步与 SQLite + IndexedDB 主存储尚未实现。
- `FamilyWorkspace` 已改为独立 Ant Design Vue 只读总览：姓名/ID/分支/别名检索、性别和分支筛选、分页名录、全字段人物档案、世代统计、事件与寻根轨迹浏览。谱载代数与相对树层级分开展示；未录父亲不等于已确认始祖。
- 图谱继续使用 ECharts，重做横纵向切换、展开层级、选中节点展开/收起、保留祖先路径的分支视图、人物及后代子树、重置视图与 PNG 导出。按可见节点数量分配画布空间并在容器内滚动，避免把数百个节点压到固定高度重叠；不使用 ECharts 私有模型接口定位。连线只表示已记录父系，配偶/过继/待匹配声明在档案中明确区分，不自动合并同名或同音异字。
- 点击图谱节点只选中并展开/收起后代，叶节点只选中；通过“查看档案”独立打开详情。手动折叠状态在选人、搜索、横纵向切换和数据刷新时保留，搜索只展开目标祖先路径；改变展开层级、切换子树或“重置视图”会清除手动覆盖。重绘移除隐藏后代的节点与连线，保留缩放与漫游中心，展开/收起尽量锚定点击位置。
- 未录父亲但有谱载代数依据的人物，在图谱中与同辈对齐，筛选分支仍使用全谱层级；无代数依据者从第 1 层起算。对齐仅使用不可见的排版占位，不新增人物、不补造父亲或连线；“查看所选子树”则从所选人物的第 1 层重新排版。
- Markdown 导入已修复子女声明边界、姓名与尾注拆分、男女/继嗣分段及嵌套孙辈误挂。按用户确认的可靠长幼顺序，优先精确姓名匹配；姓名不符或同名冲突时，仅在同分支、下一世代、父亲记载和排行唯一一致时自动关联，保留双方原字，不改名、不合并人物。亲生与承继分别核对排行，出继仍属生父序列；承继异名关联须有对应继/嗣/养父记载及完整的同性别承继正文组。没有明确长次时，只有同父、同性别记录完整且顺序无冲突才按原文排序推定；缺字和无目标的状态记载保留排行空位，有解析疑点时不启用排行推定。预览显示带行号的解析与关联依据，全部未匹配项可分页核对；确认前不写入云端。
- 出继与承继分开记录：`parentId` 保留生父，`adoptive-parent` 关系保留承继父，不以继父覆盖生父。同分支同代的两条同名正文，只有生父出继、兄弟承继及双处正文对应唯一时才整理为一份档案，保留两处原文并重连配偶、后代和声明；不是按同名一律合并。缺少明确出继对应的同名记录继续待核对，已有承继父关联者不误算为孤立成员。
- 验证指定谱文可运行 `npm run verify:part-data-v2 -- data/20260501.md`（也可传其他本地路径）。命令严格校验 schema 并向标准输出打印 JSON 统计和完整诊断，不生成报告文件、不保存数据，也不以孤立人数阈值代替正确性检查。默认谱文是本地资料，不作为普通测试的必需输入。
- **发布验收尚未完成**：本地完整回归已通过，原有 19 条 Markdown 边界失败已修复；这不代表生产环境、所有目标浏览器与性能指标已验收。检查记录见 [实施记录](docs/stage3.md)，实际 Workers 部署路径见 [部署指南](docs/deploy-cloudflare-pages.MD)。OCR、离线同步、PDF/CSV 与关系路径查询不属于本轮完成范围。
- 开发环境继续使用 npm 工作区，无需 pnpm：`npm ci`、`npm run dev`；验证命令为 `npm test`、`npm run build`。需使用支持 ES2023 数组方法的现代浏览器。

## 产品化：第二批登录（v0.1.4）

- 登录默认只填写已登记手机号，账号需要密码时再显示密码框，不要求用户选择角色。普通用户仍无密码、无短信验证码；维护人员使用各自密码，sysadmin 沿用原有服务端固定验证密码。首次初始化收纳到次要入口。
- 系统管理员在账号管理中为维护人员设置初始密码或重置密码（8 至 128 位，不能全为空白）；未设置密码的旧维护账号不可继续免密登录。密码只保存独立随机盐的摘要，不返回客户端，也不包含在族谱业务备份中。
- 角色、手机号、启停状态或维护密码变更会使旧会话失效，必须重新登录；仅修改名称不退出。升级会阻止旧维护人员免密会话继续使用，但保留未变更的普通用户和 sysadmin 会话。
- Worker 自动补齐认证字段；`migrations/0003_maintainer_passwords.sql` 仅供尚未自动升级的旧库手动迁移，不可重复执行。部署前须准备旧维护账号的密码设置与告知流程；迁移和回滚注意事项见 [登录说明](docs/Login.md)。
- `v0.1.3` 及更早版本的维护人员原本按手机号免密登录；升级到 `v0.1.4` 后须由系统管理员设置独立密码。只读接口与资料可见范围见下节，登录改造本身不构成资料隐私隔离。

## 产品化：浏览与维护隔离（v0.1.4）

- 按确认范围，普通用户保留全部现有族谱资料的查看权限，包括原始记载、葬地和精确寻根轨迹；不会因本次拆分丢失资料或获得增删改权限。
- 浏览使用独立的 `GET /api/browse-data` 与加载专用状态，返回版本化的九集合只读契约，不包含维护用的 `next*` 编号计数器，不初始化维护工作区或其保存版本。
- 完整维护快照的 `GET /api/family-data` 和 `PUT /api/family-data` 仅限维护人员、系统管理员；保存要求完整集合、编号计数器和修订号，浏览响应不能作为维护快照直接覆盖保存。浏览接口没有写入操作，账号管理仍仅限系统管理员。
- 浏览首页提供可关闭的首次使用提示和使用指南；不再提示仅保存本机显示偏好，不保存身份资料。帮助同时说明登录问题、账号登记和管理边界。
- 升级后旧客户端需刷新。该拆分隔离读写能力，不限制已登记账号查看获准的族谱资料，也不证明手机号持有者身份；不能宣传为敏感字段隐藏或强身份验证。真机与家族用户体验验收尚待进行，Mac iPhone 镜像点击问题按决定留到整体计划完成后处理。

## 1. 产品概述

### 1.1 产品背景
传统纸质族谱查阅不便、更新困难，且难以在家族成员间共享。随着数字化普及，需要一个轻量级、跨平台的电子族谱系统，让家族成员能够便捷地记录、查看和管理家族世系，传承家族文化。

### 1.2 产品定位
一款面向家庭/家族使用的**轻量级电子族谱管理工具**，提供族谱树形可视化展示与后台管理功能，支持移动端和PC端自适应访问，当前使用 Cloudflare D1 在线存储与本地文件备份；离线编辑与同步仍属规划。

### 1.3 产品目标
- 提供直观的族谱树状图，支持缩放拖拽，方便查看多代关系。
- 提供完整的成员管理功能（增、删、改），维护家族成员信息。
- 提供家族事件记录功能，记录婚丧嫁娶等重要时刻。
- 适配移动端与PC端，确保在不同设备上均有良好体验。
- 数据持久化至 Cloudflare D1 云端，支持多设备访问与离线备份。

## 3. 核心功能需求

### 3.1 族谱可视化展示（用户端/管理端共享）
- **树状图呈现**：使用 ECharts 库生成正交树形图，虚拟根仅用于排版且不显示。未录父亲者保留独立分支，有谱载代数依据时按辈分对齐，不一律置顶。
- **交互操作**：
  - 支持鼠标/手指拖拽画布、双指缩放/滚轮缩放。
  - 点击节点选中并折叠/展开后代，“+”表示可展开，“-”表示可收起；叶节点仅选中。也可使用“展开所选”“收起所选”按钮。
  - 鼠标悬停显示成员简要信息（姓名、性别、ID）。
  - 使用“查看档案”或名录中的档案入口打开只读详情，不因展开/收起自动弹出面板；维护操作仍在管理端。

- **主存储路径**：使用 Cloudflare D1 云端数据库存储所有成员、轨迹、事件数据，支持多设备访问。
- **保存语义**：增删改与导入统一通过串行队列保存，等待云端确认；失败完整回滚，不提示假成功。

### D1 持久化结构

以下基础表为历史模型摘要；当前真实入口为 `api/index.ts`，不应将它与 SQLite 备份文件结构混同。

| 表名 | 关键字段 | 说明 |
|------|----------|------|

## 7. 交互流程与约束

### 7.1 新增成员流程
1. 用户在“族人管理”点击新增，使用 Ant Design Vue 表单弹窗填写姓名、父亲（可选）、性别、谱载代数与档案字段。
2. 点击"保存"按钮提交。
3. 系统校验姓名非空，校验通过后创建新成员并分配自增 ID。
4. 保存至 Cloudflare D1 云端，刷新树图、成员列表和父级选项。
5. 新增成功后自动选中新成员，便于继续查看或编辑。

### 7.2 编辑成员流程
1. 用户通过“族人管理”表格或档案 Drawer 进入编辑表单弹窗。
2. 修改姓名、父亲、性别或档案字段后点击"保存"。
3. 系统进行姓名非空、自引用和后代检测校验。
4. 校验通过后进入串行云端保存链路，确认成功后完成更新；失败完整回滚。
5. 若校验失败则提示错误原因并保持当前数据不变。

### 7.3 删除成员流程
1. 用户点击删除按钮。
2. 弹出确认框："确认删除 [姓名] 及其全部后代吗？预计删除 X 位成员。"。
3. 用户确认后，递归获取所有后代 ID，从成员数组中过滤删除（级联删除）。
4. 同时级联删除被删成员关联的所有事件。
5. 保存并刷新界面，提示"已删除 X 位成员"。

### 7.4 循环依赖检测规则
当编辑成员的父亲时，系统会检查：若将 A 的父亲设为 B，则 B 不能是 A 自身，也不能是 A 的后代。检测算法为基于子树遍历（DFS/栈）判断候选父节点是否位于 A 的后代集合中，若命中则拒绝操作。

### 7.5 JSON 导入导出流程
1. 用户点击"导入 JSON/SQLite"后选择本地 JSON 或 SQLite 文件。
2. 系统先弹出覆盖确认："导入将覆盖当前数据，是否继续？"。
3. 用户确认后先以共享 schema 4 契约验证并迁移数据，再进入同一串行云端保存链路；仅云端确认后提示成功，失败完整回滚并提示具体错误。
4. 用户可点击"导出 JSON"或"导出 SQLite"下载当前数据备份。
5. 导入结束后会清空文件输入状态，避免重复触发。

### 7.5.1 SQLite 导入导出流程
1. “导出 SQLite”使用 SQL.js 生成真正的 SQLite 二进制文件。
2. 文件包含 `family_backup(format_version INTEGER, payload TEXT)` 表，恰好一行；`format_version = 1`，`payload` 为 canonical JSON 业务快照（schema 4 全字段）。
3. 这是本系统的快照容器，不是 D1 整库镜像；不含登录账号和会话，也不支持导入任意 SQLite 数据库。
4. 导入兼容历史 JSON 文本伪装的 `.sqlite/.db`；无关 SQLite 文件或不支持的备份版本会拒绝。
5. 导入同样先校验，再通过可靠云端保存链路提交；成功后刷新工作区，失败保持原数据。

### 7.5.2 启动与历史数据兼容边界
1. 当前启动读取在线 D1；空库保持为空，不注入示例数据或自动上传历史 localStorage。
2. 历史 localStorage 不自动删除；云端读取或写入失败不静默切换本地存储。
3. 历史 schema 2/3 备份可由用户选择文件后显式导入，先校验、迁移再保存。
4. localStorage -> SQLite / IndexedDB 自动主存储迁移和离线编辑同步仍是规划，不能视为当前可用流程。

### 7.6 OCR 导入流程
1. 用户点击"从族谱照片导入"，上传图片或使用拍照入口。
2. 系统完成图片压缩并执行 OCR 识别。
3. 前端解析识别文本并展示可编辑预览表格。
4. 用户可修正字段并处理重复候选（跳过/新增）。
5. 点击导入后批量写入成员与关系并刷新树图。

### 7.7 事件管理流程
1. 用户在事件管理面板选择事件类型、填写标题和日期（必填），可选关联成员和说明。
2. 点击"新增事件"提交，系统校验标题和日期非空后创建事件。
3. 编辑事件：点击事件列表"编辑"按钮，表单切换为编辑态，修改后保存。
4. 删除事件：点击"删除"按钮，确认后移除事件记录。
5. 事件按日期倒序排列展示。

## 8. 技术实现说明

| 技术栈 | 用途 |
|-------|------|
| Vue 3 | 组件化界面与响应式状态驱动 |
| TypeScript | 类型约束与业务逻辑可靠性 |
| Vite | 本地开发与构建工具链 |
| ECharts ^6.1.0 | 父系树可视化、分支与子树浏览、PNG 导出 |
| Cloudflare D1 | 云端关系型数据库，主存储路径 |
| Cloudflare Workers + Static Assets | 同源业务 API 与前端资源部署；不是仅上传静态 Pages |
| SQL.js + SQLite | 生成与读取本系统二进制备份文件，非在线主存储 |
| IndexedDB | SQLite 主存储持久化尚未实现 |
| localStorage | 保留历史数据，不自动上传/删除，不作故障回退 |

### 关键技术点
- **树图数据转换**：将扁平成员数组转换为嵌套的树结构，通过虚拟根节点统一挂载。
- **搜索高亮**：搜索关键词匹配成员后，将匹配 ID 集合传递至树图组件进行节点高亮渲染。
- **自适应**：使用 `@media` 查询配合 Flex 布局。
- **移动端触摸优化**：ECharts 默认支持触摸事件，通过 `roam: true` 启用缩放拖拽。
- **关系校验**：更新父节点时执行自引用与后代检测，防止关系成环。
- **配偶兼容**：使用显式配偶记录与关系保存，兼容迁移历史 `spouseIds`。
- **事件级联删除**：删除成员时自动清理关联事件，防止悬挂引用。
- **导入导出闭环**：支持 JSON/SQLite 文件导入、覆盖确认与导出备份。
- **云端存储**：真实 Workers 入口通过 D1 batch 事务与 `If-Match` CAS 保存；store 串行写入，等待确认，失败完整回滚。
- **存储升级兼容**：共享严格 schema 4 契约兼容 schema 2/3；离线主路径、双写与故障回退未实现。
- **Toast 通知**：统一的操作反馈系统，成功/错误/信息三种类型，自动消失。

## 9. 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| 添加成员时姓名为空 | Toast 提示"姓名不能为空"，不执行添加 |
| 编辑时姓名为空 | Toast 提示，阻止保存 |
| 将父亲设为自己 | Toast 提示"父节点不能是本人或后代" |
| 形成循环依赖 | Toast 提示"父节点不能是本人或后代" |
| 删除成员不存在 | 返回"成员不存在"，不执行删除 |
| 导入 JSON 格式无效 | 提示"导入失败：JSON 格式无效" |
| 导入数据结构错误 | 提示"导入失败：数据结构错误" |
| 导入合法空快照 | 允许保存为空库，不自动填充示例数据 |
| 导入数据成员 ID 重复 | 提示"导入失败：成员 ID 重复" |
| 导入覆盖确认未通过 | 取消导入，保持原数据不变 |
| 引用不存在的成员、形成循环或 ID 重复 | 严格校验拒绝，不静默删除记录或置空引用 |
| GPX 文件格式无效 | 提示"GPX 解析失败：文件格式无效" |
| GPX 文件过大（超过 10MB） | 提示"GPX 文件过大（上限 10MB）" |
| GPX 轨迹点不足 | 提示"GPX 解析失败：轨迹点不足（至少 2 个）" |
| OCR 识别服务失败 | 提示"OCR 识别失败"，用户可重试 |
| OCR 结果无有效姓名 | 提示"OCR 导入失败：无有效成员姓名" |
| OCR 导入发现重复候选 | 提示重复处理策略，由用户选择跳过或新增 |
| SQLite 备份运行时初始化失败 | 提示错误，备份操作失败，不切换主存储 |
| SQLite 导入失败 | 提示"SQLite 导入失败"，保持原数据不变 |
| 云端保存失败或修订号冲突 | 完整回滚并提示错误；冲突需重新读取数据，不静默覆盖 |
| D1 云端连接失败 | 提示"云端 D1 数据初始化失败"，提供重试按钮 |
| 事件标题为空 | Toast 提示"事件标题不能为空"，不执行保存 |
| 事件日期为空 | Toast 提示"事件日期不能为空"，不执行保存 |
| 删除事件不存在 | 返回"事件不存在"，不执行删除 |
| 导航弹窗被拦截 | Toast 提示"导航页面被拦截，请允许弹窗后重试" |

## 附录：术语表

- **族谱**：记载家族世系和重要人物事迹的图册。
- **始祖**：家族中无父亲记录的成员，代表一个分支的起点。
- **虚拟根节点**：在树图中为了统一展示所有顶级成员而创建的非实际节点，不存储于数据中。
- **循环依赖**：将后代设为祖先的父亲，导致关系环路，属于逻辑错误。
- **家族事件**：家族中的重要时刻记录，如婚丧嫁娶、出生、逝世等。
- **世代**：成员在家族树中的层级深度，始祖为第 1 代，其子女为第 2 代，依此类推。
